# 업무 문서와 게시판

업무 파일의 일반 폴더와 날짜 업무 폴더에서 `새 문서`로 웹 문서를 작성합니다. 카드·목록·게시판은 같은 저장소를 보여줍니다. 게시판은 문서만 표로 표시하고 다른 파일과 하위 폴더는 위쪽에 표시합니다.

AI 기업의 채팅·업무 파일·설정 등 화면은 AI 스튜디오의 `nk_theme`와 `nk_theme_variant` 설정을 공유합니다. 다른 탭의 변경, 페이지 재방문, 같은 출처의 스튜디오 임베드 테마 메시지를 반영하며 화면이나 작성 중인 내용을 다시 만들지 않습니다. 문서 작성 화면은 밝은 종이 형태를 유지합니다. 공통 화면 색은 `companyTheme.css`의 의미별 색상 변수로 관리하고, 스튜디오의 10개 기본·세부 팔레트와 일치하는지 `company-theme.test.mjs`에서 검증합니다.

## 사용 방법

- 빈 문서, 업무 메모, 회의록, 업무 일지, 거래처 기록 양식을 선택합니다.
- 제목·본문·분류·상태·상단 고정을 편집합니다. 본문은 서식이 보이는 문서 화면에서 직접 작성합니다. 글자를 선택하고 제목·굵게·기울임·목록·체크·링크 버튼을 누르면 실제 서식이 적용됩니다.
- 넓은 화면에서는 제목과 보기 탭을 한 줄에, 분류·상태를 다음 줄에 배치합니다. 서식 도구는 이름 안내가 있는 아이콘으로 표시합니다. 도구 모음은 항상 두 줄이며 아래쪽 표 메뉴는 표 안에서만 활성화됩니다. 좁은 화면에서는 도구 줄을 가로로 스크롤할 수 있습니다.
- 왼쪽·가운데·오른쪽 정렬은 현재 문단 또는 선택한 문단에 적용됩니다. 제목, 목록, 표 안의 문단도 정렬할 수 있으며 저장·미리보기에도 유지됩니다.
- 편집과 미리보기는 같은 문서 화면을 사용합니다. 미리보기에서는 본문 수정을 막고 편집 도구를 감춥니다. 글꼴·서식·표·줄 간격·여백이 같고 전환 시 실행 취소 이력을 유지합니다.
- 표의 셀을 직접 수정하고 행·열을 추가하거나 삭제할 수 있습니다. 체크박스는 편집 화면에서 변경합니다. 실행 취소·다시 실행 버튼과 Ctrl/Cmd+Z 단축키를 지원합니다.
- 표 셀을 클릭한 뒤 `셀 색상`에서 연한 기본 색 6가지 중 하나를 고릅니다. 여러 셀을 선택했다면 함께 적용됩니다. `색 지우기`로 기본 배경으로 되돌립니다. 색 변경도 저장 버튼을 눌러야 저장됩니다.
- 문서는 `저장` 버튼 또는 Ctrl/Cmd+S를 누를 때만 저장합니다. 입력 중에는 자동 저장하지 않으며 저장하지 않은 변경 사항을 표시합니다. 저장 오류가 나면 내용을 유지합니다. 수정 후 저장 버튼으로 재시도합니다.
- 저장하지 않은 문서 변경이 있으면 댓글 등록·이력 복원 전에 먼저 저장하도록 안내합니다. 이 작업들이 본문을 자동 저장하지 않습니다. 문서를 닫거나 페이지를 떠날 때도 저장하지 않은 변경 사항을 확인합니다.
- 이미지 붙여넣기 및 이미지·파일 첨부를 지원합니다. 파일당 20MB까지 허용합니다. `본문 다운로드`는 마크다운 본문을 내려받습니다. 첨부 파일은 문서에서 각각 내려받습니다.
- 댓글, 최근 수정 이력 조회, 이전 판 복원을 지원합니다. 복원은 현재 내용을 이력에 추가하고 댓글은 유지합니다.
- Word·한글 파일 자체의 편집 기능은 포함하지 않습니다. 첨부하거나 기존 파일 미리보기·다운로드를 사용합니다.

## 저장과 충돌

문서는 사용자별 기존 GCS `company-files` 공간에 `.nkdoc.json` 파일로 저장합니다. 본문과 댓글, 이력을 한 객체로 관리하고 게시판 목록에 필요한 요약만 객체 메타데이터에 함께 기록합니다. 별도 DB 마이그레이션은 없습니다.

서식 편집기는 Tiptap을 사용하며, `content`는 기존과 같은 마크다운 문자열입니다. 에이전트의 문서 읽기·수정 API와 본문 다운로드 형식은 유지합니다. 기존 문서를 열거나 보기 방식을 전환하는 것만으로 원문을 변경하지 않습니다. 본문을 실제로 편집하면 같은 서식을 나타내는 마크다운으로 변환하며, 명시적으로 저장할 때 기록합니다. 줄바꿈·표·체크·첨부 주소는 왕복 변환 테스트로 검증합니다.

셀 배경색이나 문단 정렬이 있는 블록은 마크다운 본문 안에 HTML로 저장합니다. 셀의 `style="background-color: #rrggbb"`와 `data-cell-color`에 색이, 문단·제목의 `style="text-align: left|center|right"`에 정렬이 들어갑니다. 허용된 값만 읽고 표시합니다. 에이전트도 기존 `content`를 읽고 수정하는 방식으로 서식을 유지할 수 있습니다. 셀 색과 문단 정렬이 없는 표는 일반 마크다운 표로 저장합니다.

GCS `generation`을 문자열로 전달하며 `ifGenerationMatch`로 원자적으로 저장합니다. 생성은 `"0"`, 수정은 읽기 결과의 generation을 사용합니다. 다른 창이나 에이전트가 먼저 저장하면 HTTP 409로 중단합니다. 현재 작성 내용을 복사해 보관한 뒤 문서를 다시 열어 최신 내용에 반영합니다. 생성 실패·충돌을 성공으로 표시하지 않습니다.

본문은 100,000자, 제목은 120자, 분류는 40자까지입니다. 댓글은 4,000자씩 최대 200개, 수정 이력은 최대 20개이며 전체 객체가 4MB를 넘으면 가장 오래된 이력을 먼저 제거합니다. 첨부는 같은 사용자 공간의 `.document-attachments`에 저장하여 문서나 상위 폴더를 이동·복사해도 링크가 유지됩니다. 첨부 객체는 이력·복사본이 참조할 수 있어 문서 삭제와 함께 자동 삭제하지 않습니다.

일반 파일 업로드·write·edit 도구가 웹 문서를 덮어쓰는 것은 막습니다. 복사·이동·삭제는 기존 파일 작업을 사용합니다. 로그인한 계정의 공간만 접근하며 기존 파일 API의 인증을 적용합니다.

## 에이전트 도구

모든 직원 에이전트에 다음 도구를 제공합니다. 읽기는 즉시 실행하고, 변경은 기존 파일 도구와 동일한 앱 내 승인 절차를 따릅니다.

| 도구 | 기능 |
| --- | --- |
| `company_files_list` / `company_files_search` | 폴더 목록·문서 검색 |
| `company_files_document_read` | 본문·댓글·generation·수정 이력 요약 조회 |
| `company_files_document_save` | 문서 생성, 본문·제목·분류·상태·고정 수정 |
| `company_files_document_comment` | 댓글 추가 |
| `company_files_document_restore` | revision으로 이전 판 복원 |
| `company_files_copy` / `company_files_move` / `company_files_delete` | 복사·이동·삭제 |

기존 문서는 먼저 읽어 경로와 generation을 확인합니다. save는 전달한 필드만 바꾸며 본문 변경 시 완성된 전체 content를 전달합니다. 댓글과 이력은 서버가 보존합니다. 에이전트가 남긴 수정·댓글은 실행 작업의 소유 계정을 확인한 뒤 담당 직원 ID로 표시합니다. 채팅의 문서 카드에서도 같은 편집기를 엽니다.

예: “Account 폴더에 오늘 회의록을 만들어 줘”, “이 회의록에 결정 사항을 추가하고 검토 중으로 바꿔 줘”, “확인한 내용을 댓글로 남겨 줘”.

## 검증

`prototype/tests/company-documents.test.mjs`는 생성·읽기·부분 필드 갱신·댓글·복원·목록 메타데이터, 중복 생성과 경쟁 저장, 인증·계정 격리, 일반 파일 도구의 덮어쓰기 차단, 모든 직원의 도구 등록을 검증합니다. 전체 테스트는 저장소의 `npm test`, 프런트 빌드는 `ai-company-app`의 `npm run build`입니다.

GCS 저장 전제조건은 [공식 Objects: insert 문서](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/insert)를 따릅니다.
