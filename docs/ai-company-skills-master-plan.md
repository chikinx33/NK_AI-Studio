# 라비오크 AI 회사 스킬 마스터 기획서

> 문서 버전: 1.0  
> 기준일: 2026-07-19  
> 기준 레지스트리: `ai-company-app/src/lib/companySkills.ts`  
> 적용 대상: 라비오크 AI 회사의 Skill 메뉴, 에이전트 직접 지시, 회사 업무 탐색기  
> 현재 운영 상태: `디자인·콘텐츠 > 인포그래픽 영상`만 활성화

## 1. 문서 목적

이 문서는 라비오크 AI 회사를 실제 회사처럼 운영하기 위해 필요한 생산성 업무를 **대분류 Skill과 세부 Skill**로 구조화하고, 각 세부 Skill의 사용자 화면, 에이전트 협업, 실행 절차, 산출물, 저장 방식, 권한, 비용, 품질 기준을 정의한다.

이 문서를 다음 작업의 단일 기준으로 사용한다.

- 신규 Skill 구현 순서와 범위 결정
- 공통 UI와 Skill별 전용 UI 설계
- 채팅 지시와 직접 실행 화면의 동작 일치
- 에이전트 역할 및 업무 보고 형식 정의
- 산출물의 회사 업무 탐색기 저장 규칙 정의
- 외부 서비스 연결, 비용 발생, 승인 필요 작업 구분
- Skill 활성화 전 완료 조건과 품질 검사

이 문서에서 말하는 **Skill**은 Codex의 `SKILL.md` 패키지가 아니라 라비오크 제품 안에서 사용자가 수행하는 회사 업무 유형을 뜻한다.

## 2. 핵심 용어

| 용어 | 정의 |
| --- | --- |
| 대분류 Skill | 우측 사이드바에 아이콘으로 표시되는 업무 영역. 예: 디자인·콘텐츠 |
| 세부 Skill | 대분류 페이지에서 단일 선택하는 실제 업무. 예: 이미지 제작 |
| 업무(Job) | 사용자의 한 번의 지시로 생성되는 실행 단위 |
| 산출물(Artifact) | 업무가 만든 영상, 이미지, 문서, 코드, 데이터 등의 파일과 메타데이터 |
| 작업 원본(Source) | 재편집에 필요한 프롬프트, 장면 명세, 템플릿, JSON, 소스 코드 등 |
| 호출 방식 | `agent`: 채팅으로 에이전트에게 지시, `manual`: Skill 화면에서 직접 입력 |
| 업무 탐색기 | 날짜별 폴더와 업무별 항목으로 산출물을 열람·이름 변경·다운로드·삭제하는 화면 |
| 품질 게이트 | 완료 처리 전에 자동 또는 사람 승인으로 통과해야 하는 검사 |

## 3. 제품 원칙

### 3.1 두 가지 실행 방식, 하나의 업무 엔진

모든 세부 Skill은 두 방식으로 실행한다.

1. 사용자가 일반 채팅에서 코어에게 직접 지시한다.
2. 사용자가 우측 `Skill` 아이콘을 누르고 세부 Skill을 선택한 뒤 전용 UI에서 `작업 시작`을 누른다.

두 방식은 입력 수집 방법만 다르다. 실행기, 진행 상태, 에이전트 협업, 산출물 저장, 업무 탐색기 항목은 동일해야 한다. 채팅용 기능과 화면용 기능을 별도로 구현하지 않는다.

### 3.2 사용자 대신 일을 끝내는 구조

- 사용자는 필요한 결과와 제약 조건을 말하고, 에이전트가 기획·제작·검수·저장을 수행한다.
- 필수 정보가 이미 지시에 있으면 반복해서 질문하지 않는다.
- 누락된 값은 안전한 기본값으로 채울 수 있을 때 자동 결정하고 업무 보고에 기록한다.
- 결과가 기준에 미달하면 완료로 표시하지 않고 자동 수정 단계로 되돌린다.
- 발송, 게시, 삭제, 결제, 일정 확정처럼 외부 상태를 바꾸는 작업은 별도 승인을 받는다.

### 3.3 모든 결과는 회사 자산

- 완료된 업무는 반드시 `company_work_items`와 회사 업무 탐색기에 등록한다.
- 최종 파일뿐 아니라 작업 원본, 미리보기, 실행 명세, 품질 검사 결과를 함께 보관한다.
- 사용자가 이름을 바꾸어도 실제 생성일, Skill ID, 원본 업무 ID는 유지한다.
- 같은 업무의 재작업은 새 업무를 무분별하게 만들지 않고 버전으로 연결한다.
- 모든 조회와 저장은 `userId`를 기준으로 격리한다.

### 3.4 품질과 비용을 숨기지 않는다

- 결과물 종류에 맞는 자동 검사와 시각 검수를 모두 수행한다.
- 유료 모델, 음성 합성, 생성형 영상, 외부 렌더링을 사용할 경우 실행 전에 예상 비용과 무료 대안을 표시한다.
- 로컬 생성과 오픈소스 도구만 사용하는 경우 외부 생성 비용은 `0원`으로 표시할 수 있다. 다만 모델 대화 비용과 사용자의 PC 자원은 별도다.

## 4. 공통 화면 설계

### 4.1 진입 구조

- 우측 사이드바의 `Skill` 영역에는 대분류 아이콘만 한 행으로 표시한다.
- 활성화된 대분류는 주황색 아이콘과 선택 상태를 표시한다.
- 미구현 대분류는 비활성 상태로 두고 클릭 시 `준비 중`만 안내한다.
- 대분류 화면 상단에는 `COMPANY SKILLS`, 대분류명, 닫기 버튼을 둔다.
- 세부 Skill은 박스나 설명 문구 없이 단일 선택 라디오 항목으로 표시한다.
- 한 세부 Skill을 선택하면 나머지는 자동 해제된다.

### 4.2 공통 작업 화면

데스크톱에서는 내부 스크롤 없이 한 화면에서 핵심 상태를 파악할 수 있도록 다음 세 영역을 배치한다.

| 영역 | 역할 | 공통 요소 |
| --- | --- | --- |
| 개요 | 사용자의 목표와 제약 입력 | 필수값, 선택값, 참조 파일, 예상 비용, `작업 시작` |
| 미리보기 | 결과 또는 진행 중 초안 확인 | 종류별 뷰어, 버전 선택, 확대/축소, 오류 상태 |
| 업무 보고 | 에이전트별 판단과 진행 과정 | 현재 단계, 결정 사항, 경고, 품질 검사, 실패 원인 |

반응형 규칙은 다음과 같다.

- 넓은 화면: `개요 / 미리보기 / 업무 보고` 3열.
- 좁은 화면: 개요를 접을 수 있게 하고 미리보기와 업무 보고를 순차 배치.
- 세로형 영상·이미지: 미리보기 높이를 화면 안에 맞추고 장면·버전 카드는 오른쪽 세로 열에 배치.
- 1:1 결과물: 원본 비율을 유지하며 남는 공간은 작업 배경으로 처리하고 콘텐츠를 늘이지 않는다.
- 긴 목록은 카드 내부가 아니라 화면의 보조 패널 또는 모달에서 처리한다.

### 4.3 공통 버튼과 상태

| 상태 | 기본 버튼 | 동작 |
| --- | --- | --- |
| 입력 중 | 작업 시작 | 입력 검증 후 업무 생성 |
| 실행 중 | 작업 중… | 중복 실행 방지를 위해 비활성화 |
| 검수 중 | 검수 중… | 자동 품질 검사와 수정 진행 |
| 완료 | 결과 종류에 맞는 행동 | 다운로드, 저장, 초안 열기, 승인 요청 등 |
| 실패 | 다시 시도 | 실패 지점부터 재개 |
| 취소 가능 | 작업 취소 | 현재 실행을 중단하고 부분 결과 보존 |

인포그래픽의 완료 버튼은 `다운로드`를 사용한다. 메일·일정처럼 외부 변경이 있는 Skill은 `발송 승인`, `일정 등록 승인`처럼 행동을 명확히 표현한다.

### 4.4 공통 입력 요소

- 업무 요청: 자유 서술. 모든 Skill의 기본 입력이다.
- 대상/독자: 결과를 읽거나 보는 사람.
- 목적: 알림, 설득, 분석, 기록, 판매 등.
- 톤: 브랜드 말투 또는 결과물의 정서.
- 참조 자료: 파일, URL, 회사 지식, 기존 업무 산출물.
- 브랜드: 로고, 색상, 폰트, 금지 표현.
- 마감/우선순위: 선택 사항.
- 비용 정책: 무료 우선, 품질 우선, 한도 지정.
- 민감정보 표시: 개인정보·기밀 포함 여부.

Skill별 화면에서는 필요한 항목만 노출하고 고급 옵션은 접힌 영역에 둔다.

## 5. 공통 실행 및 데이터 구조

### 5.1 업무 상태 모델

```text
draft → validating → planning → running → reviewing → completed
                    ↘ failed ↗          ↘ revision ↗
                    ↘ cancelled
```

- `draft`: 입력 중이거나 채팅 지시를 해석한 상태
- `validating`: 필수 정보, 권한, 연결 서비스, 비용 확인
- `planning`: 코어가 에이전트와 실행 계획 및 산출물 명세 작성
- `running`: 실제 제작·분석·작성 수행
- `reviewing`: 자동 검사, 시각 검수, 사실 검증
- `revision`: 검사 실패 항목을 자동 수정
- `completed`: 최종 산출물 저장과 업무 탐색기 등록 완료
- `failed`: 복구 가능한 오류와 사용자 조치가 필요한 오류를 구분
- `cancelled`: 사용자가 취소했으며 생성된 중간 파일은 보존 정책에 따라 정리

페이지 이동이나 PC 재시작으로 진행 상태가 초기화되지 않도록 서버 상태를 기준으로 복원한다.

### 5.2 Skill 정의 모델

각 세부 Skill은 최소한 다음 정보를 레지스트리에 가진다.

```ts
type CompanySkillDefinition = {
  id: string;
  categoryId: string;
  label: string;
  status: 'available' | 'coming-soon';
  inputSchema: string;
  executorId: string;
  previewType: string;
  artifactTypes: string[];
  requiredCapabilities: string[];
  permissionPolicy: string;
  costPolicy: string;
  qualityGateIds: string[];
};
```

현재 `companySkills.ts`의 표시용 정보에 위 실행 메타데이터를 단계적으로 추가한다. 기존 인포그래픽 API는 즉시 폐기하지 않고 공통 업무 엔진의 어댑터로 연결한다.

### 5.3 업무와 산출물

업무에는 다음 핵심 필드를 저장한다.

- `id`, `userId`, `conversationId`, `companyId`
- `categoryId`, `skillId`, `invocationMode`
- `title`(20자 이내 표시, 초과 시 UI에서 말줄임), `originalTitle`
- `status`, `progress`, `currentStage`
- `input`, `resolvedBrief`, `executionPlan`
- `agentReports`, `warnings`, `error`
- `costEstimate`, `actualCost`, `providerUsage`
- `qualityResults`, `approvalState`
- `createdAt`, `updatedAt`, `completedAt`
- `parentWorkId`, `version`, `lineage`

산출물은 업무와 1:N 관계로 저장하며 다음 종류를 구분한다.

- `source`: 재편집 가능한 원본
- `preview`: 브라우저 미리보기용 저용량 파일
- `final`: 최종 다운로드 파일
- `manifest`: 입력, 결정, 버전, 파일 목록을 담은 JSON
- `report`: 품질 검사 및 업무 수행 기록

### 5.4 저장 경로

클라우드 저장소의 논리 경로는 다음 형식을 사용한다.

```text
users/{userId}/ai-company/work-library/{YYYY-MM-DD}/{workId}/
  manifest.json
  source/
  preview/
  final/
  reports/
```

업무 탐색기에서 날짜 폴더명과 업무명을 변경해도 물리 경로의 `YYYY-MM-DD`와 `workId`는 변경하지 않는다. 사용자에게 보이는 이름은 데이터베이스 메타데이터로 관리한다.

### 5.5 공통 API 목표

```text
POST   /api/agent/skills/{skillId}/jobs
GET    /api/agent/skill-jobs/{jobId}
POST   /api/agent/skill-jobs/{jobId}/cancel
POST   /api/agent/skill-jobs/{jobId}/retry
POST   /api/agent/skill-jobs/{jobId}/approve
GET    /api/agent/skill-jobs/{jobId}/artifacts
```

직접 실행과 채팅 실행은 첫 번째 API에 동일한 `SkillJobInput`을 전달하며 `invocationMode`만 다르게 기록한다.

## 6. 에이전트 협업 표준

코어는 업무 총괄과 최종 승인을 담당한다. 나머지 에이전트는 실제 등록된 역할 레지스트리를 기준으로 배정하며, 대표 역할은 다음과 같다.

| 역할 | 대표 에이전트 | 책임 |
| --- | --- | --- |
| 총괄·통합 | 코어 | 요청 해석, 역할 배정, 충돌 해결, 완료 판단 |
| 구조·스토리 | 플롯 | 정보 구조, 순서, 내러티브, 화면/문서 구성 |
| 문안 | 잉크 | 제목, 본문, 요약, 카피, 언어 품질 |
| 시각 설계 | 픽셀 | 레이아웃, 브랜드, 이미지, 차트, 접근성 |
| 음향 | 비트 | 음악, 효과음, 음성, 음량과 타이밍 |
| 조사 | 레이더 | 자료 수집, 출처, 최신성, 근거 분류 |
| 분석 | 엣지 | 데이터 검증, 비교, 계산, 인사이트 |
| 운영 보조 | 싱크 | 일정, 정리, 변환, 반복 작업 |
| 마케팅·배포 | 리치/마키 | 채널 적합성, 캠페인, 고객 접점 |

모든 업무에 모든 에이전트를 투입하지 않는다. Skill 정의의 `requiredCapabilities`를 바탕으로 필요한 역할만 선택한다. UI의 업무 보고에는 이름 앞 이모지를 사용하지 않고, 다음 형식으로 기록한다.

- 에이전트명
- 상태: 대기 / 진행 / 완료 / 수정 / 실패
- 수행한 결정과 근거
- 생성·수정한 산출물
- 남은 위험 또는 사용자 승인 항목

## 7. 권한·비용·보안 정책

### 7.1 권한 단계

| 단계 | 예 | 정책 |
| --- | --- | --- |
| 로컬·초안 생성 | 문서 초안, 이미지, 분석 보고서 | 지시 범위 안에서 자동 실행 |
| 외부 읽기 | 메일 조회, 캘린더 조회, 웹 자료 수집 | 연결 계정과 읽기 범위 확인 |
| 외부 쓰기 | 메일 발송, 일정 생성, 게시, PR 작성 | 실행 전 명시적 승인 |
| 파괴적 변경 | 삭제, 일정 취소, 파일 덮어쓰기 | 대상 재확인과 명시적 승인 |
| 금전 영향 | 광고 집행, 유료 모델 대량 호출 | 예상 비용과 상한 승인 |

### 7.2 비용 표시

실행 전 다음 중 하나를 표시한다.

- `추가 외부 비용 없음`: 로컬/기존 무료 자원만 사용
- `예상 비용`: 사용량과 공급자 단가를 기반으로 범위 표시
- `계정 요금제에 포함`: 연결 서비스의 기존 구독 범위
- `산정 불가`: 실행 전 공급자 확인이 필요하며 자동 시작 금지

실제 비용은 업무 완료 후 업무 보고와 `manifest.json`에 기록한다.

### 7.3 보안

- API 키와 OAuth 토큰을 업무 입력 또는 산출물에 저장하지 않는다.
- 메일, 인사, 고객 자료의 민감정보는 미리보기와 로그에서 최소화한다.
- 외부 자료를 모델에 보낼 때 사용자·회사 정책과 공급자 데이터 정책을 확인한다.
- 코드 실행, 업로드 파일, 압축 파일은 격리 환경에서 검사한다.

## 8. 공통 품질 게이트

모든 Skill은 다음 공통 검사를 통과해야 한다.

1. **요청 충족**: 목적, 대상, 형식, 길이, 언어, 마감 조건을 충족한다.
2. **내용 무결성**: 빈 영역, 임시 문구, 누락된 페이지, 잘린 텍스트가 없다.
3. **사실성**: 조사 기반 주장은 출처와 연결되고 추정은 추정으로 표시한다.
4. **브랜드 준수**: 지정 로고, 색상, 폰트, 금지 표현을 지킨다.
5. **접근성**: 읽을 수 있는 크기, 명도 대비, 자막 또는 대체 설명을 제공한다.
6. **파일 검증**: 결과 파일이 열리고 손상되지 않았으며 확장자와 실제 형식이 일치한다.
7. **개인정보·기밀**: 의도하지 않은 민감정보 노출이 없다.
8. **시각 검수**: 문서·슬라이드·이미지·영상은 실제 렌더 결과를 캡처해 시각적으로 검사한다.
9. **재현성**: 원본과 실행 명세만으로 동일 업무를 다시 열거나 수정할 수 있다.
10. **저장 확인**: 최종 산출물과 manifest가 업무 탐색기에서 열리고 다운로드된다.

## 10. 대분류별 상세 기획

### 10.1 디자인·콘텐츠

#### 10.1.1 인포그래픽 영상 — `infographic`

- **목표/산출물**: 복잡한 메시지를 장면별 시각 구조와 모션으로 전달하는 MP4 인포그래픽. `MP4`, 저용량 미리보기, 장면 명세 JSON, 썸네일, 품질 보고서를 저장한다.
- **개요 UI**: 영상 요청, 길이, 화면비, 시청 대상, 톤, 시각 스타일, 브랜드, 참고 자료, 음향 사용, 비용 정책. 현재 구현을 공통 Skill UI의 기준으로 사용한다.
- **미리보기 UI**: Remotion Player, 장면 카드, 장면별 길이·제목·시각 문법·음향 표시. 세로형은 플레이어를 화면 높이에 맞추고 장면 카드를 오른쪽에 세로 배치한다.
- **업무 보고**: 플롯의 장면 구성, 잉크의 문안, 픽셀의 레이아웃, 비트의 음향, 코어의 최종 명세와 품질 검사 결과.
- **실행**: 요청을 장면별 `Render Manifest`로 변환하고 Remotion 컴포지션을 선택·구성한다. 단순히 텍스트만 바꾸는 단일 템플릿 반복을 금지하고 내용에 따라 차트·흐름·비교·목록·타임라인 등 시각 문법을 선택한다.
- **전용 품질 게이트**: 화면비 실제 일치, 최소 글자 크기, 명도 대비, 안전 여백, 장면별 정보 밀도, 빈 카드·잘린 텍스트·겹침 없음, 음량 피크와 SFX 타이밍, 최종 프레임 캡처 검수.
- **의존성/상태**: 현재 활성. Remotion 로컬 렌더, 클라우드 저장소, 업무 탐색기와 연결되어야 한다.

#### 10.1.2 이미지 제작 — `image`

- **목표/산출물**: 제품 이미지, 일러스트, 콘셉트 아트, 배경, 인물, 소셜 이미지 등을 신규 생성하거나 기존 이미지를 편집한다. `PNG/JPG/WebP`, 투명 배경 파일, 미리보기, 프롬프트와 편집 명세를 저장한다.
- **개요 UI**: 작업 방식(`새 이미지 / 이미지 편집 / 변형 / 배경 제거·교체 / 리사이즈·확장`), 사용 목적, 이미지 설명, 대상 채널, 화면비 또는 픽셀 크기, 결과 개수, 스타일, 브랜드, 참조 이미지, 반드시 유지할 요소, 금지 요소, 배경 투명 여부, 품질·비용 우선순위.
- **조건부 UI**: 편집 모드에서는 원본 업로드, 편집 지시, 유지 영역과 수정 영역을 받는다. 참조 기반 모드에서는 참조 강도와 인물·제품 일관성 여부를 받는다. 텍스트 포함 시 정확한 문구와 언어를 별도 필드로 받는다.
- **미리보기 UI**: 후보 그리드, 확대 뷰, 원본/결과 비교 슬라이더, 선택·탈락 표시, 실제 사용 크기 미리보기, 버전 이력. 사용자가 대표 결과를 선택하거나 코어가 품질 점수로 대표안을 지정한다.
- **업무 보고**: 픽셀의 시각 방향과 후보 생성, 잉크의 이미지 내 문구, 코어의 후보 비교·선정, 실패한 요소와 재생성 기록.
- **실행**: 요청을 구조화된 이미지 브리프로 변환하고 적합한 이미지 생성·편집 공급자를 선택한다. 배경 제거와 리사이즈처럼 결정적 작업은 생성 모델 대신 로컬 도구를 우선한다.
- **전용 품질 게이트**: 해상도·비율·알파 채널, 왜곡된 손·얼굴·제품, 잘못 생성된 문자, 로고 훼손, 참조 일관성, 워터마크, 중복 후보, 색상 대비를 실제 이미지로 검사한다.
- **승인/비용**: 유료 이미지 API 사용 전 예상 후보 수와 비용을 표시한다. 외부 게시나 원본 덮어쓰기는 별도 승인한다.
- **활성화 조건**: 공통 이미지 작업 명세, 공급자 어댑터, 후보 선택 UI, 시각 QA, 회사 업무 탐색기 저장이 완료되어야 한다.

#### 10.1.3 PPT·슬라이드 — `presentation`

- **목표/산출물**: 발표 목적에 맞는 편집 가능한 `PPTX`, 배포용 `PDF`, 미리보기 이미지, 발표자 노트와 사용 자료 목록.
- **개요 UI**: 발표 목적, 대상, 발표 시간, 슬라이드 수, 화면비, 언어, 핵심 메시지, 필수 목차, 브랜드·템플릿, 참고 자료, 데이터·차트 필요 여부, 발표자 노트 여부.
- **미리보기 UI**: 왼쪽 슬라이드 썸네일, 가운데 현재 슬라이드, 오른쪽 업무 보고. 개요와 스토리라인 보기, 슬라이드 순서 변경, 버전 비교를 지원한다.
- **업무 보고**: 플롯의 전체 서사, 레이더의 근거, 엣지의 수치, 잉크의 문안, 픽셀의 마스터·레이아웃, 코어의 최종 검수.
- **실행**: 먼저 슬라이드별 목적과 핵심 문장을 확정한 뒤 시각 시스템을 생성하고 실제 PPTX로 제작한다. 텍스트를 이미지로 평면화하지 않는다.
- **전용 품질 게이트**: 글자·도형 넘침, 폰트 대체, 대비, 정렬, 중복 레이아웃, 차트 수치, 페이지 번호, 발표 시간 대비 정보량을 렌더된 전 페이지 이미지로 검사한다.
- **활성화 조건**: PPTX 생성·렌더·검증 파이프라인, 템플릿/브랜드 매핑, 슬라이드 미리보기, 파일 다운로드가 완료되어야 한다.

#### 10.1.4 카드뉴스 — `card-news`

- **목표/산출물**: 연속해서 읽는 소셜 카드 콘텐츠. 카드별 `PNG`, 전체 `ZIP`, 검토용 `PDF`, 카피·배치 명세를 저장한다.
- **개요 UI**: 플랫폼, 카드 수, 화면비, 주제, 대상, 핵심 메시지, 카드 흐름, CTA, 톤, 브랜드, 참고 자료.
- **미리보기 UI**: 카드 스트립과 선택 카드 확대, 모바일 실제 크기 보기, 앞뒤 카드 연결 보기, 순서 변경.
- **업무 보고**: 플롯의 카드 서사, 잉크의 카드별 한 문장, 픽셀의 일관된 레이아웃과 시각 요소, 코어의 가독성 검수.
- **전용 품질 게이트**: 첫 카드 주목성, 카드별 한 가지 메시지, 글자 크기, 안전 영역, 번호·순서, CTA, 전체 시각 일관성.
- **활성화 조건**: 이미지/레이아웃 엔진과 다중 파일 패키징이 먼저 완성되어야 한다.

#### 10.1.5 포스터·배너 — `poster-banner`

- **목표/산출물**: 인쇄 포스터와 디지털 채널별 배너. 규격별 이미지, 인쇄용 PDF, 원본 명세를 저장한다.
- **개요 UI**: 용도, 채널 또는 인쇄 규격, 필수 문구, 날짜·장소·가격, CTA, 로고, 이미지, 브랜드, 변형 규격 수, 인쇄 여백과 재단선.
- **미리보기 UI**: 규격별 탭, 실제 크기 축소 보기, 안전 영역/재단선 토글, 채널 목업.
- **업무 보고**: 잉크의 메시지 우선순위, 픽셀의 시선 흐름과 규격 변형, 코어의 필수 정보 누락 검사.
- **전용 품질 게이트**: 픽셀 크기·DPI·색상 모드, 재단 여백, 필수 문구, 대비, 로고 비율, CTA 가독성.
- **활성화 조건**: 이미지 제작 Skill의 레이아웃·시각 QA 모듈과 규격 프리셋을 재사용한다.

#### 10.1.6 영상·숏폼 — `video-shortform`

- **목표/산출물**: 광고, 설명, SNS 숏폼 등 독립 영상 제작. `MP4`, 자막 `SRT/VTT`, 썸네일, 대본, 장면 명세, 오디오 정보를 저장한다. AI Cinema의 프리·메인·포스트 프로덕션과 분리된 Skill이다.
- **개요 UI**: 플랫폼, 목적, 길이, 화면비, 대본 또는 핵심 메시지, 보유 영상·이미지, 생성 장면 필요 여부, 자막 스타일, 내레이션, 음악·SFX, CTA, 브랜드, 비용 상한.
- **미리보기 UI**: 영상 플레이어, 장면·클립 타임라인, 자막 트랙, 오디오 상태, 장면 카드. 자동 제작 결과를 먼저 보여주고 필요한 경우 장면 단위 재생성을 제공한다.
- **업무 보고**: 플롯의 대본·컷 구성, 잉크의 자막·카피, 픽셀의 화면, 비트의 음성·음악·SFX, 코어의 연속성과 정책 검수.
- **실행**: 제공 자산, 생성 이미지/영상, Remotion 모션, TTS, `@remotion/sfx` 등을 장면 명세에 따라 조립한다. 생성형 실사 영상은 별도 공급자와 비용 승인이 있어야 한다.
- **전용 품질 게이트**: 장면 맥락과 순서, 프레임 손상, 자막 싱크·안전 영역, 오디오 피크, 음성 명료도, 무음 구간, 저작권·라이선스, 플랫폼 규격.
- **활성화 조건**: 공통 미디어 자산 관리, 음향 정책, 렌더 큐, 비용 한도와 실패 복구가 필요하다.

#### 10.1.7 썸네일 — `thumbnail`

- **목표/산출물**: 영상·콘텐츠 클릭을 유도하는 채널별 썸네일 후보. `PNG/JPG`, A/B 후보와 평가표를 저장한다.
- **개요 UI**: 플랫폼, 콘텐츠 제목·요약, 대상, 핵심 훅, 정확한 표시 문구, 인물·제품 이미지, 브랜드, 후보 수, 금지 표현.
- **미리보기 UI**: 후보 그리드, 실제 피드 크기 보기, 밝은/어두운 UI 배경 보기, 모바일·데스크톱 비교, 대표안 선택.
- **업무 보고**: 잉크의 훅 문구, 픽셀의 시선 유도와 후보 차별화, 마케팅 역할의 클릭 맥락 검토, 코어의 선정 이유.
- **전용 품질 게이트**: 축소 가독성, 인물·제품 식별, 문구 정확성, 과장·오해 가능성, 후보 간 실질적 차이, 플랫폼 안전 영역.
- **활성화 조건**: 이미지 제작 Skill과 채널별 프리셋이 먼저 활성화되어야 한다.

### 10.2 문서·오피스

#### 10.2.1 보고서·기획서 — `report`

- **목표/산출물**: 조사 보고서, 사업·실행 기획서, 내부 보고 문서를 `DOCX/PDF/Markdown`으로 제작한다.
- **개요 UI**: 문서 종류, 목적, 독자, 분량, 마감, 필수 목차, 핵심 질문, 참고 자료, 템플릿·브랜드, 언어와 문체, 인용 방식.
- **미리보기 UI**: 목차 트리, 페이지 미리보기, 근거·인용 패널, 버전 비교. 먼저 개요를 확정한 뒤 본문이 채워지는 과정을 보여준다.
- **업무 보고**: 플롯의 목차, 레이더의 출처, 엣지의 분석, 잉크의 본문, 픽셀의 문서 스타일, 코어의 최종 검토.
- **전용 품질 게이트**: 목차-본문 일치, 근거 없는 주장, 표·그림 번호, 페이지 나눔, 고아 문장, 헤더·푸터, 링크와 인용 유효성.
- **활성화 조건**: DOCX 생성·페이지 렌더·PDF 변환·시각 검수 파이프라인이 필요하다.

#### 10.2.2 스프레드시트 — `spreadsheet`

- **목표/산출물**: 새 워크북 제작, 데이터 정리, 계산, 차트·대시보드를 포함한 `XLSX/CSV` 결과를 만든다.
- **개요 UI**: 작업 유형(`신규 / 분석 / 정리 / 통합 / 대시보드`), 원본 파일, 필요한 시트, 열 정의, 계산 규칙, 핵심 지표, 차트, 출력 형식, 데이터 보존 규칙.
- **미리보기 UI**: 시트 탭, 표 미리보기, 수식 표시, 변경 전후 요약, 차트, 데이터 검증 경고.
- **업무 보고**: 엣지의 데이터 프로파일과 계산, 싱크의 정리·변환, 픽셀의 차트, 코어의 수식·행 수 검증.
- **전용 품질 게이트**: 행·열 수 보존, 형식·단위, 수식 오류, 빈값·중복 처리, 필터·동결, 차트 범위, 재계산 결과.
- **승인**: 원본 파일 덮어쓰기와 외부 시트 반영은 별도 승인한다.
- **활성화 조건**: 안전한 파일 파서, 수식 계산, XLSX 렌더·검증, 대용량 제한이 필요하다.

#### 10.2.3 PDF 제작·편집 — `pdf`

- **목표/산출물**: PDF 신규 생성, 병합, 분할, 순서 변경, 회전, OCR, 워터마크, 일부 편집·가림 처리를 수행한다.
- **개요 UI**: 작업 방식, 원본 파일 목록, 페이지 범위와 순서, OCR 언어, 워터마크, 출력 품질, 암호화, 가림 영역.
- **미리보기 UI**: 페이지 썸네일, 드래그 순서 변경, 선택 페이지 확대, 작업 전후 비교, 텍스트 추출 확인.
- **업무 보고**: 싱크의 페이지 작업, 잉크의 OCR 확인, 픽셀의 페이지 품질, 코어의 누락·손상 검사.
- **전용 품질 게이트**: 페이지 수와 순서, 글꼴·이미지 품질, 검색 가능 여부, 링크, 메타데이터, 가림 정보의 실제 제거 여부.
- **승인**: 되돌리기 어려운 가림, 암호 제거, 전자서명 관련 작업은 대상과 법적 책임을 명확히 확인한다.
- **활성화 조건**: PDF 렌더·검사, OCR, 안전한 병합·분할, 미리보기 생성이 필요하다.

#### 10.2.4 회의록 — `meeting-minutes`

- **목표/산출물**: 녹음·영상·전사·메모에서 요약, 결정 사항, 실행 항목을 추출해 `DOCX/PDF/Markdown` 회의록으로 만든다.
- **개요 UI**: 회의명, 일시, 참석자, 목적, 입력 자료, 회의록 형식, 요약 수준, 실행 항목 담당자·기한 표기, 민감도.
- **미리보기 UI**: 전사 타임라인, 핵심 요약, 결정 사항, 미결 사항, 실행 항목 표. 원문 위치로 이동할 수 있어야 한다.
- **업무 보고**: 싱크의 전사 정리, 잉크의 요약, 코어의 결정·담당자 검증.
- **전용 품질 게이트**: 발언자와 시간, 실제 결정과 제안 구분, 담당자·기한의 근거, 누락된 불확실성 표시, 오디오 구간 연결.
- **비용/승인**: 외부 음성 전사 서비스를 쓰면 예상 비용을 표시한다. 실행 항목을 프로젝트나 캘린더에 등록할 때 승인받는다.
- **활성화 조건**: 미디어 전사, 화자 분리, 근거 타임스탬프, 문서 출력이 필요하다.

#### 10.2.5 업무 템플릿 — `template`

- **목표/산출물**: 반복 업무에 사용할 문서·표·브리프·체크리스트 템플릿과 입력 스키마를 만든다.
- **개요 UI**: 템플릿 종류, 사용 상황, 사용자 역할, 필수·선택 필드, 반복 항목, 계산·검증 규칙, 출력 형식, 예시 데이터, 브랜드.
- **미리보기 UI**: 입력 폼 미리보기, 결과 샘플, 필드 스키마, 검증 오류, 버전 이력.
- **업무 보고**: 플롯의 구조, 싱크의 필드·자동화, 잉크의 안내 문구, 코어의 재사용성 검토.
- **전용 품질 게이트**: 빈 예시·실데이터 혼동 방지, 필수값 검사, 비밀정보 기본값 금지, 버전 호환, 실제 샘플 생성 성공.
- **활성화 조건**: 템플릿 레지스트리, 버전 관리, 다른 Skill에서 템플릿을 불러오는 공통 선택기가 필요하다.

### 10.3 조사·분석

#### 10.3.1 웹 리서치 — `web-research`

- **목표/산출물**: 특정 질문을 최신 공개 자료로 조사해 출처가 연결된 보고서와 소스 목록을 만든다.
- **개요 UI**: 조사 질문, 범위, 국가·언어, 기준 시점, 깊이, 선호·제외 출처, 결과 형식, 인용 방식, 마감.
- **미리보기 UI**: 조사 계획, 검색 쿼리, 출처 목록, 핵심 발견, 주장-출처 연결표, 불확실성.
- **업무 보고**: 레이더의 수집·출처 평가, 엣지의 비교, 잉크의 요약, 코어의 결론.
- **전용 품질 게이트**: 최신성, 1차 자료 우선, 서로 다른 출처 교차검증, 링크 유효성, 발행일과 사건일 구분, 인용 한도 준수.
- **활성화 조건**: 웹 검색 도구, 출처 저장, 인용 렌더러, 도메인·기간 필터가 필요하다.

#### 10.3.2 시장·경쟁사 분석 — `market-analysis`

- **목표/산출물**: 시장 규모, 동향, 경쟁 포지션, 기회·위험을 비교한 `DOCX/PDF/PPTX/XLSX` 분석 패키지를 만든다.
- **개요 UI**: 시장 정의, 지역, 기간, 경쟁사, 비교 항목, 고객군, 핵심 사업 질문, 내부 자료, 원하는 산출물.
- **미리보기 UI**: 시장 구조, 경쟁사 매트릭스, 데이터 표·차트, 기회·위험, 전략 시사점, 출처.
- **업무 보고**: 레이더의 시장 자료, 엣지의 수치·비교, 플롯의 분석 구조, 코어의 가정과 결론 검증.
- **전용 품질 게이트**: 시장 범위 일관성, 통화·기간·단위 통일, 추정치와 사실 구분, 경쟁사 최신성, 수치 산식과 출처.
- **활성화 조건**: 웹 리서치와 데이터 분석 Skill의 공통 모듈이 먼저 필요하다.

#### 10.3.3 데이터 분석 — `data-analysis`

- **목표/산출물**: 업로드 데이터나 연결 데이터에서 통계, 시각화, 인사이트를 도출하고 재현 가능한 결과를 만든다.
- **개요 UI**: 데이터 파일·연결, 질문, 목표 변수, 기간, 필터, 지표 정의, 결측·이상치 처리, 원하는 차트·보고 형식, 개인정보 여부.
- **미리보기 UI**: 데이터 프로파일, 정리 로그, 분석 단계, 표·차트, 핵심 발견, 다운로드 가능한 정제 데이터.
- **업무 보고**: 엣지의 분석과 검증, 싱크의 정리, 픽셀의 시각화, 코어의 과해석·누락 검사.
- **전용 품질 게이트**: 원본·정제 행 수, 결측 처리 기록, 단위, 표본 크기, 계산 재현, 통계적 한계, 차트 축 왜곡, 개인정보 노출.
- **활성화 조건**: 격리 분석 런타임, 데이터 크기 제한, 재현 스크립트, 표·차트 렌더가 필요하다.

#### 10.3.4 자료 요약 — `source-summary`

- **목표/산출물**: 여러 문서·URL·파일을 목적에 맞게 요약하고 비교·쟁점·근거 지도를 만든다.
- **개요 UI**: 자료 업로드·URL, 요약 목적, 독자, 길이, 요약 방식(`개별 / 통합 / 비교`), 중점 질문, 인용·번역 여부.
- **미리보기 UI**: 자료별 탭, 핵심 포인트, 공통점·차이, 충돌하는 주장, 원문 위치와 인용.
- **업무 보고**: 레이더의 자료 분류, 잉크의 압축, 엣지의 비교, 코어의 누락과 왜곡 검토.
- **전용 품질 게이트**: 자료별 출처 분리, 서로 다른 주장의 잘못된 결합 방지, 원문 의미 보존, 페이지·문단 근거, 빠진 자료 표시.
- **활성화 조건**: 문서 파서, URL 수집, 긴 문서 분할, 출처 위치 매핑이 필요하다.

### 10.4 소통·일정

#### 10.4.1 메일 확인·분류 — `email-triage`

- **목표/산출물**: 연결된 메일함을 긴급, 답변 필요, 대기, 참고 등으로 분류하고 처리 제안을 만든다.
- **개요 UI**: 계정, 기간, 검색 조건, 폴더·라벨, 중요 발신자, 제외 조건, 분류 규칙, 읽기 범위.
- **미리보기 UI**: 분류별 목록, 발신자·제목·요약·기한, 추천 행동, 원문 열기. 기본값은 읽기 전용이다.
- **업무 보고**: 싱크의 분류, 잉크의 요약, 코어의 우선순위와 애매한 항목.
- **전용 품질 게이트**: 검색 범위, 중복 스레드, 실제 회신 필요 여부, 날짜·시간대, 피싱·의심 링크 표시, 민감정보 최소 노출.
- **승인/연결**: Gmail 또는 Outlook 연결과 읽기 권한이 필요하다. 읽음 처리, 이동, 라벨 변경은 사용자가 승인한 규칙에 한해 실행한다.
- **활성화 조건**: 메일 커넥터, OAuth 범위, 스레드 정규화, 감사 로그가 필요하다.

#### 10.4.2 메일 작성·회신 — `email-draft`

- **목표/산출물**: 신규 메일 또는 기존 스레드의 회신 초안을 작성하고 승인 후 발송한다.
- **개요 UI**: 계정, 받는 사람·참조, 목적, 관련 스레드, 전달할 내용, 톤, 언어, 기한, 첨부 파일, 서명.
- **미리보기 UI**: 제목, 본문, 수신자, 첨부, 스레드 문맥, 발송 전 체크리스트. 버전 비교와 문장별 수정이 가능하다.
- **업무 보고**: 잉크의 초안, 싱크의 수신자·첨부 확인, 코어의 사실·톤·요청 사항 검수.
- **전용 품질 게이트**: 수신자·호칭, 날짜·금액, 첨부 누락, 회신 질문 누락, 민감정보, 잘못된 약속, 맞춤법.
- **승인**: 초안 저장은 자동 가능하나 실제 발송은 항상 `발송 승인`을 거친다.
- **활성화 조건**: 메일 커넥터, 초안 저장, 첨부 처리, 발송 승인과 감사 로그가 필요하다.

#### 10.4.3 일정·캘린더 — `calendar`

- **목표/산출물**: 일정 조회, 가능한 시간 탐색, 일정 초안 생성, 변경·취소를 지원한다.
- **개요 UI**: 작업 유형, 캘린더, 참석자, 기간, 시간대, 소요 시간, 근무 시간, 장소·화상회의, 반복, 충돌 허용 여부.
- **미리보기 UI**: 주간 캘린더, 참석자 가능 시간, 충돌, 일정 상세, 변경 전후 비교.
- **업무 보고**: 싱크의 시간 탐색, 코어의 조건 충족과 충돌 판단.
- **전용 품질 게이트**: 시간대, 공휴일·근무 시간, 중복 일정, 참석자 주소, 반복 규칙, 알림, 회의 링크.
- **승인**: 조회는 자동 가능하며 생성·변경·취소는 실제 반영 전에 승인받는다.
- **활성화 조건**: Google/Outlook Calendar 연결, free/busy 조회, 승인 가능한 변경안 모델이 필요하다.

#### 10.4.4 회의 준비 — `meeting-prep`

- **목표/산출물**: 회의 목적과 자료를 바탕으로 의제, 사전 읽기, 질문, 결정 항목, 참석자 브리프를 준비한다.
- **개요 UI**: 회의명·일시, 목적, 참석자, 회의 시간, 관련 프로젝트·메일·자료, 필요한 결정, 민감도.
- **미리보기 UI**: 시간 배분 의제, 참석자별 맥락, 핵심 자료 요약, 예상 질문, 결정·후속 조치 템플릿.
- **업무 보고**: 레이더의 배경 자료, 플롯의 의제, 싱크의 일정·참석자, 코어의 준비도 검토.
- **전용 품질 게이트**: 의제 시간 합계, 자료 최신성, 참석자 권한에 맞는 정보, 결정 질문의 명확성, 관련 링크.
- **승인**: 의제 메일 발송 또는 캘린더 첨부는 승인 후 실행한다.
- **활성화 조건**: 자료 요약, 메일·캘린더 읽기, 문서 생성 모듈이 필요하다.

### 10.5 마케팅·영업

#### 10.5.1 캠페인 기획 — `campaign`

- **목표/산출물**: 목표, 고객 여정, 채널, 콘텐츠, 일정, 예산, KPI를 포함한 캠페인 계획을 만든다.
- **개요 UI**: 캠페인 목표, 제품·제안, 대상, 기간, 지역, 채널, 예산, KPI, 브랜드, 경쟁 자료, 법적 제약.
- **미리보기 UI**: 전략 한 장 요약, 고객 여정, 채널별 계획, 콘텐츠 캘린더, 예산 배분, KPI 대시보드.
- **업무 보고**: 레이더의 시장·고객 근거, 리치/마키의 채널 전략, 잉크의 메시지, 엣지의 예산·KPI, 코어의 통합.
- **전용 품질 게이트**: 목표-KPI 연결, 예산 합계, 일정 충돌, 채널 규격, 근거 없는 성과 예측, 광고·표시 규정.
- **승인**: 광고 집행, 게시 예약, 예산 사용은 별도 승인한다.
- **활성화 조건**: 리서치, 카피, 콘텐츠 제작, 일정 모듈을 조합하는 상위 Skill로 구현한다.

#### 10.5.2 광고·세일즈 카피 — `copywriting`

- **목표/산출물**: 광고, 랜딩페이지, 영업 메시지, 제품 설명 등 채널별 카피 후보와 사용 가이드를 만든다.
- **개요 UI**: 채널, 목적, 제품·서비스, 대상, 가치 제안, 근거, CTA, 톤, 글자 수, 필수·금지 문구, 후보 수.
- **미리보기 UI**: 후보별 제목·본문·CTA, 글자 수, 채널 목업, 차이점과 추천안.
- **업무 보고**: 레이더의 고객 근거, 잉크의 카피, 마케팅 역할의 채널 적합성, 코어의 사실·정책 검토.
- **전용 품질 게이트**: 글자 수, 필수 문구, 근거 없는 최상급·효능 주장, 중복 후보, CTA 명확성, 브랜드 말투.
- **활성화 조건**: 브랜드 보이스, 금지 표현, 채널별 글자 제한 레지스트리가 필요하다.

#### 10.5.3 제안서 — `proposal`

- **목표/산출물**: 고객 문제, 해결안, 범위, 일정, 가격, 기대 효과를 담은 `PPTX/PDF/DOCX` 제안서를 만든다.
- **개요 UI**: 고객, 제안 목적, 문제, 해결안, 범위·제외 범위, 일정, 가격·조건, 사례, 담당자, 템플릿, 기밀 등급.
- **미리보기 UI**: 제안 흐름, 페이지·슬라이드 미리보기, 범위표, 일정표, 가격표, 가정·위험.
- **업무 보고**: 레이더의 고객 맥락, 플롯의 설득 구조, 잉크의 문안, 엣지의 가격 계산, 픽셀의 디자인, 코어의 조건 검토.
- **전용 품질 게이트**: 가격 합계·세금, 기간, 범위 일치, 고객명·담당자, 사례 권한, 기밀 표시, 근거 없는 보장.
- **승인**: 외부 고객 발송과 최종 가격 확정은 승인받는다.
- **활성화 조건**: PPT·문서 생성, 계산 검증, 고객·브랜드 템플릿이 필요하다.

#### 10.5.4 고객 응대 — `customer-response`

- **목표/산출물**: 문의·불만·지원 티켓의 답변 초안, 해결 절차, 에스컬레이션 제안을 만든다.
- **개요 UI**: 채널, 고객·티켓, 문의 내용, 관련 주문·정책, 원하는 결과, 톤, SLA, 보상 권한, 언어.
- **미리보기 UI**: 고객 답변, 내부 메모, 근거 정책, 다음 단계, 에스컬레이션 여부.
- **업무 보고**: 싱크의 사실 정리, 레이더의 정책 조회, 잉크의 답변, 코어의 약속·권한 검토.
- **전용 품질 게이트**: 고객 정보, 정책 근거, SLA, 해결 단계, 금지된 보상·약속, 감정적 표현, 개인정보.
- **승인**: 실제 발송, 환불·보상, 계정 변경은 각각 권한 있는 사용자의 승인을 받는다.
- **활성화 조건**: 고객 시스템 연결, 정책 지식, 승인·에스컬레이션 모델이 필요하다.

### 10.6 개발·자동화

#### 10.6.1 웹페이지 — `web-page`

- **목표/산출물**: 랜딩페이지, 대시보드, 포털, 내부 도구 등 실행 가능한 웹페이지 소스와 빌드 결과를 만든다.
- **개요 UI**: 페이지 유형, 목표, 대상, 섹션, 기능, 브랜드, 참조 사이트, 반응형 범위, 기술 스택, 데이터 연결, 배포 여부.
- **미리보기 UI**: 실제 실행 샌드박스, 데스크톱·태블릿·모바일 전환, 화면 목록, 접근성·성능 보고, 변경 파일.
- **업무 보고**: 플롯의 정보 구조, 픽셀의 UI, 개발 역할의 구현·테스트, 코어의 요구사항·보안 검수.
- **전용 품질 게이트**: 빌드·테스트, 콘솔 오류, 반응형, 키보드 탐색, 명도 대비, 성능, 입력 검증, 비밀정보 포함 여부.
- **승인**: 로컬 소스 변경은 지정 작업 범위에서 수행할 수 있으나 외부 배포·도메인 변경은 승인받는다.
- **활성화 조건**: 격리 개발 런타임, 프리뷰 서버, 소스·빌드 저장, 배포 어댑터가 필요하다.

#### 10.6.2 기능 개발 — `feature-development`

- **목표/산출물**: 기존 코드베이스에 요구 기능을 구현하고 변경 파일, 테스트 결과, 사용법을 남긴다.
- **개요 UI**: 저장소·작업공간, 요구사항, 범위, 인수 조건, 기술 스택, 관련 화면·파일, 테스트 수준, 브랜치·배포 정책.
- **미리보기 UI**: 구현 계획, 파일 변경 목록과 diff, 실행 화면, 테스트 결과, 남은 위험.
- **업무 보고**: 분석·개발 역할의 원인과 설계, 픽셀의 UI 확인, 코어의 인수 조건 검증.
- **전용 품질 게이트**: 기존 규칙 준수, 테스트, 빌드, 회귀, 오류 처리, 보안, 사용자 변경 보존, 문서·버전 업데이트.
- **승인**: 커밋·푸시·PR·배포 정책은 저장소별 규칙과 사용자의 명시적 범위를 따른다.
- **활성화 조건**: 안전한 저장소 접근, 변경 추적, 테스트 런너, 장기 작업 상태 복원이 필요하다.

#### 10.6.3 코드 검토 — `code-review`

- **목표/산출물**: 코드 변경을 읽기 전용으로 검토하고 심각도, 파일·줄, 근거, 수정 방향이 포함된 리뷰를 만든다.
- **개요 UI**: 저장소, 기준·대상 브랜치 또는 파일, 검토 범위, 중점 영역, 프로젝트 규칙, 테스트 실행 여부.
- **미리보기 UI**: 심각도별 발견 목록, diff, 파일·줄 위치, 재현 증거, 테스트 결과, 전체 요약.
- **업무 보고**: 검토 역할의 분석, 코어의 중복 제거·우선순위 확정.
- **전용 품질 게이트**: 실제 변경으로 발생한 문제인지, 재현 가능성, 파일·줄 정확성, 과도한 추정 방지, 테스트 근거.
- **승인**: 기본은 코드를 수정하지 않는다. 자동 수정, 리뷰 댓글 게시, PR 승인은 별도 행동이다.
- **활성화 조건**: Git diff 파서, 프로젝트 규칙 로더, 테스트 실행, 인라인 위치 매핑이 필요하다.

#### 10.6.4 업무 자동화 — `workflow-automation`

- **목표/산출물**: 트리거, 조건, 앱 동작, 승인, 오류 처리를 연결한 자동화 정의와 운영 문서를 만든다.
- **개요 UI**: 업무 목표, 트리거, 실행 주기, 입력 앱·출력 앱, 조건, 데이터 매핑, 실패 처리, 재시도, 승인 지점, 알림, 비용 한도.
- **미리보기 UI**: 흐름도, 단계별 입출력, 테스트 실행, 로그, 실패 분기, 권한 목록.
- **업무 보고**: 싱크의 흐름 구성, 개발 역할의 연결·검증, 코어의 권한·비용·무한 반복 검사.
- **전용 품질 게이트**: 샘플 실행, 중복 실행 방지, 멱등성, 재시도·타임아웃, 비밀정보, 권한 최소화, 감사 로그.
- **승인**: 자동화 활성화와 외부 쓰기 단계는 승인받고 언제든 비활성화할 수 있어야 한다.
- **활성화 조건**: 커넥터 허브, 스케줄러, 비밀 저장소, 실행 로그, 중지 장치가 필요하다.

### 10.7 경영·지원

#### 10.7.1 프로젝트 관리 — `project-management`

- **목표/산출물**: 목표를 일정, 마일스톤, 작업, 담당, 의존성, 위험으로 구조화하고 진행 상황을 관리한다.
- **개요 UI**: 프로젝트 목표, 범위, 팀, 마감, 마일스톤, 우선순위, 작업 방식, 기존 자료, 보고 주기.
- **미리보기 UI**: 로드맵, 칸반, 간트, 담당자별 작업, 의존성, 위험·이슈, 변경 이력.
- **업무 보고**: 플롯의 작업 구조, 싱크의 일정·상태, 엣지의 위험·진척, 코어의 범위와 우선순위.
- **전용 품질 게이트**: 모든 작업의 담당·완료 조건, 일정 의존성, 과부하, 기준일, 상태 합계, 위험 대응.
- **승인**: 외부 프로젝트 도구에 작업 할당·상태 변경·알림 전송 시 승인 정책을 따른다.
- **활성화 조건**: 내부 작업 모델, 일정 연결, 상태 변경 감사 로그가 필요하다.

#### 10.7.2 KPI·경영 보고 — `kpi-report`

- **목표/산출물**: 기간별 KPI, 목표 대비 실적, 추세, 원인, 다음 행동을 경영진용 보고서·대시보드로 만든다.
- **개요 UI**: 보고 기간, 지표·정의, 목표, 데이터 소스, 비교 기간, 조직, 독자, 보고 형식, 강조할 질문.
- **미리보기 UI**: KPI 카드, 추세 차트, 목표 대비 차이, 원인, 위험, 다음 행동, 데이터 최신 시각.
- **업무 보고**: 엣지의 계산·분석, 싱크의 데이터 취합, 잉크의 경영 요약, 픽셀의 대시보드, 코어의 결론.
- **전용 품질 게이트**: 지표 정의·단위, 목표·실적 기간, 계산식, 합계, 최신성, 차트 축, 원인과 상관관계의 과장 방지.
- **활성화 조건**: 스프레드시트·데이터 분석·보고서 모듈과 데이터 연결이 필요하다.

#### 10.7.3 인사·온보딩 — `hr-onboarding`

- **목표/산출물**: 직무별 입사 준비, 일정, 교육, 계정·장비, 체크리스트, 안내 문서를 구성한다.
- **개요 UI**: 입사자, 직무, 팀, 시작일, 근무 형태, 담당자, 필요한 계정·장비, 교육, 정책, 수습 목표, 민감도.
- **미리보기 UI**: 입사 전·첫날·첫 주·30/60/90일 타임라인, 담당자별 체크리스트, 일정, 안내 문서.
- **업무 보고**: 싱크의 일정·체크리스트, 잉크의 안내, 코어의 누락·권한 검토.
- **전용 품질 게이트**: 개인정보 최소화, 시작일·시간대, 담당자, 필수 정책, 계정 권한 최소화, 퇴사자 자료 혼입 방지.
- **승인**: 계정 생성, 권한 부여, 메일·일정 발송은 인사 또는 관리자의 승인을 받는다.
- **활성화 조건**: 문서·캘린더·메일·프로젝트 모듈과 역할 기반 권한이 필요하다.

#### 10.7.4 규정·정책 — `policy`

- **목표/산출물**: 회사 규정·업무 정책의 초안, 개정안, 변경 비교표, 승인 이력을 `DOCX/PDF`로 만든다.
- **개요 UI**: 정책 분야, 적용 대상, 관할 지역, 목적, 효력일, 기존 정책, 근거 자료, 필수 조항, 승인자, 검토 주기.
- **미리보기 UI**: 목차, 조항별 초안, 근거, 기존 버전과 변경 비교, 영향 받는 업무, 승인 흐름.
- **업무 보고**: 레이더의 근거 수집, 잉크의 조항 문안, 싱크의 버전·배포 계획, 코어의 불확실성과 검토 항목.
- **전용 품질 게이트**: 관할·기준일, 용어 일관성, 상충 조항, 책임·예외·시행일, 근거, 변경 이력, 법률 자문 필요 표시.
- **승인**: 자동 생성 결과는 초안이며 법무·인사 등 권한자의 검토 없이 시행·배포하지 않는다.
- **활성화 조건**: 웹 리서치, 문서 생성, 버전 비교, 승인 워크플로가 필요하다.

## 11. 대분류별 공통 페이지 확장

각 대분류 페이지는 동일한 골격을 유지하되 미리보기 컴포넌트를 결과물에 맞게 교체한다.

| 문서·오피스 | 페이지 뷰어, 스프레드시트 그리드 | 목차, 수식, 페이지 작업 |

| 소통·일정 | 메일 뷰어, 캘린더 | 수신자·권한, 충돌, 승인 |

## 13. 세부 Skill 구현 절차

새로운 세부 Skill은 다음 순서를 반드시 따른다.

1. **기획 확정**: 이 문서의 목표·입력·미리보기·산출물·품질 게이트를 제품 요구사항으로 분리한다.
2. **사용자 흐름**: 채팅 호출과 직접 UI 호출 각각의 정상·실패·취소 흐름을 설계한다.
3. **입력 스키마**: 필수값, 기본값, 조건부 필드, 파일 제한을 JSON Schema로 정의한다.
4. **실행 계약**: 에이전트 역할, 도구, 공급자, 비용, 권한, 타임아웃을 정의한다.
5. **전용 UI**: 공통 레이아웃 슬롯에 입력과 미리보기 컴포넌트를 구현한다.
6. **산출물 저장**: source, preview, final, manifest, report를 업무 탐색기와 연결한다.
7. **품질 게이트**: 자동 검사와 실제 렌더 시각 검사를 구현한다.
8. **복구**: 새로고침·탭 전환·PC 재시작 후 상태 복원, 재시도, 취소를 검증한다.
9. **테스트**: 단위, API 계약, 통합, 시각 회귀, 권한·사용자 격리 테스트를 수행한다.
10. **활성화**: 모든 완료 조건을 통과한 뒤 레지스트리 상태를 `available`로 바꾼다.

## 14. 세부 Skill 완료 정의(Definition of Done)

아래 항목을 모두 충족해야 사용자에게 활성화한다.

- 채팅 지시와 직접 UI에서 같은 품질의 결과가 생성된다.
- 직접 UI에 필요한 입력만 노출되고 조건부·고급 옵션이 정상 동작한다.
- 실행 중 버튼이 비활성화되고 탭 이동 후에도 진행 상태가 유지된다.
- 중복 업무가 생성되지 않으며 취소와 실패 재시도가 동작한다.
- 업무 보고에 실제 에이전트 판단과 오류가 순서대로 표시된다.
- 미리보기는 결과물의 실제 파일 또는 실제 렌더 소스를 사용한다.
- 최종 파일, 작업 원본, manifest, 품질 보고서가 저장된다.
- 업무 탐색기에서 원클릭 열기, 이름 변경, 다운로드, 삭제가 동작한다.
- 사용자 계정 간 데이터가 완전히 격리된다.
- 유료 호출 전에 비용이 표시되고 상한을 초과하지 않는다.
- 외부 발송·게시·변경·삭제가 승인 없이 실행되지 않는다.
- 결과 유형별 품질 게이트와 공통 품질 게이트를 통과한다.
- 모바일·세로형·1:1 등 지원 규격에서 레이아웃이 깨지지 않는다.
- 테스트, 앱 버전 갱신, 문서, 커밋·푸시까지 완료된다.

## 15. 테스트 전략

### 15.1 공통 계약 테스트

- 모든 Skill ID가 대분류에 유일하게 속한다.
- `available` Skill은 입력 스키마, 실행기, 미리보기, 품질 게이트를 가진다.
- 세부 Skill은 한 번에 하나만 선택된다.
- `agent`와 `manual` 호출이 동일한 정규화 입력을 만든다.
- 상태 전이가 허용된 방향으로만 진행된다.

### 15.2 사용자 격리·권한 테스트

- 다른 사용자의 업무, 파일, 날짜 폴더를 조회·수정·삭제할 수 없다.
- 외부 쓰기 작업은 승인 토큰 없이 실패한다.
- 승인 내용과 실제 실행 대상이 다르면 실행하지 않는다.
- 취소·재시도·삭제가 정확한 업무 ID에만 적용된다.

### 15.3 산출물·시각 테스트

- 모든 최종 파일을 실제로 열고 페이지·프레임·시트를 렌더한다.
- 대표 화면비, 긴 한글, 영문 혼합, 빈 입력, 매우 긴 입력을 검증한다.
- 밝은/어두운 배경에서 대비와 잘림을 검사한다.
- 손상 파일, 공급자 실패, 네트워크 중단, PC 재시작을 재현한다.

### 15.4 Skill별 골든 시나리오

각 세부 Skill마다 최소 3개를 유지한다.

1. 일반적인 정상 업무
2. 파일·자료·제약이 많은 복잡 업무
3. 실패 또는 승인 필요 업무

골든 결과는 동일한 디자인을 강제하는 템플릿이 아니라 내용 적합성, 구조, 파일 무결성, 품질 점수의 기준으로 사용한다.

### 18.3 현재 이어서 작업할 위치

- 현재 단계: `Phase 0 — 에이전트 업무 보고 이벤트 표준 연결`
- 마지막 완료 단위: 렌더 완료 시 MP4·편집 원본·업무 보고·manifest를 SHA-256, 버전, 계보와 함께 사용자·업무 격리 산출물 레코드로 등록
- 검증 결과: 루트 `npm test` 290개 통과, `ai-company-app` 프로덕션 빌드 통과, 산출물 API 서버 함수 esbuild 번들 통과
- 바로 다음 일감: 단계별 에이전트 업무 보고 이벤트 저장 모델과 추가·복원 API 구현
- 그다음 일감: 비용 예상·승인·상한 공통 게이트와 공통 3열 레이아웃 슬롯 분리
- 주의: 현재 최종 MP4와 네 종류 산출물 등록은 브라우저에서 업무를 열어 로컬 Remotion 렌더가 완료될 때 수행된다. 채팅 지시만 하고 결과 업무를 열지 않은 경우 서버 명세는 완료되지만 최종 MP4 artifact는 아직 생성되지 않는다. Phase 0 실DB 실패 복구 검증도 남아 있다.
