# 프리프로덕션 시나리오 프롬프트 규정 (NK_Studio)

본 문서는 2026-03-20 기준 프리프로덕션 시나리오 생성 품질을 끌어올리기 위한 기준 문서다.  
핵심 목표는 단순 생성이 아니라 `사용자가 개요에서 설정한 항목에 충실한 시나리오`를 안정적으로 만드는 것이다.

## 1. 제품 목표
- 사용자가 `주제`, `장르`, `세부 장르`, `시청 타겟`, `시청 목적`, `영상 길이`, `화면 비율`, `톤`, `스타일`, `브랜드 규칙`을 지정하면 결과 시나리오는 그 설정을 읽은 흔적이 아니라 `그 설정 때문에 그렇게 만들어진 구조`를 보여야 한다.
- 같은 주제라도 개요 값이 달라지면 시나리오의 씬 구조, 설명 방식, 참여 방식, 말투, 정보 밀도, 전개 리듬이 실제로 달라져야 한다.
- NK_Studio의 차별점은 여기서 나온다. `예쁘게 말하는 범용 시나리오`가 아니라 `개요에 강하게 정렬된 시나리오`를 만들어야 한다.

## 2. 현재 문제 정의
- 현재 구조는 개요 항목을 모델에 전달하지만, 각 항목을 `반드시 지켜야 하는 생성 규칙`으로 충분히 승격하지 못한다.
- 장르, 세부 장르, 목적, 톤, 타겟이 결과에 약하게만 반영되면 주제만 바뀐 범용 시나리오가 반복된다.
- 생성 후에도 결과물이 개요에 충실한지 검사하는 품질 게이트가 부족하면, 표면적으로만 맞는 결과도 그대로 통과한다.
- 시나리오 본질보다 카메라 문구나 형식 보정이 앞서면, 내용은 빈약한데 겉모습만 정리된 결과가 나오기 쉽다.

## 3. 기본 원칙
- 개요 입력값은 참고 정보가 아니라 `생성 계약`이다.
- 모델에게 해석을 맡기기 전에 서버가 먼저 개요를 구조화해야 한다.
- 프롬프트는 `입력 라벨 나열`보다 `성공 조건과 금지 조건 명시`가 우선이다.
- 생성 후에는 반드시 `개요 적합도 검사`를 통과해야 한다.
- 부족한 결과는 그대로 저장하지 않고 교정 또는 재생성한다.
- 짧은 영상일수록 자유 생성보다 `길이별 블루프린트`가 우선한다.
- 폴백 시나리오도 범용 문구가 아니라 개요 기반 템플릿이어야 한다.

## 4. 개요 항목 해석 규정

### 4.1 Topic(주제)
- 주제는 소재 이름이 아니라 `핵심 행위 + 핵심 대상 + 전달 방식`까지 추출 가능한 입력으로 본다.
- 예: `ABC 동요 배우기`
  - 핵심 대상: `ABC`
  - 핵심 행위: `배우기`
  - 전달 방식: `동요`
- 생성기는 Topic을 그대로 쓰지 말고 먼저 의미 단위로 분해해야 한다.

### 4.2 Genre(장르) + Subgenre/Tags(세부 장르)
- 장르와 세부 장르는 시나리오 전개 방식과 씬의 역할을 결정한다.
- 각 장르/세부 장르에는 별도의 `실행 규칙`이 있어야 한다.
- 단순 라벨 전달로 끝내지 않는다.
- 예:
  - `키즈 · 영유아`: 짧은 문장, 명확한 행동, 반복, 높은 직관성
  - `키즈 놀이`: 시청자 참여 유도, 따라 하기, 몸동작/호응
  - `동요`: 후렴 또는 반복 훅, 리듬감, 구간 반복
  - `지식 · 교양`: 정확성, 과장 억제, 이해 우선

### 4.3 Audience(시청 타겟)
- 타겟은 단순 라벨이 아니라 어휘 난이도, 문장 길이, 설명 방식, 예시 선택, 장면 밀도에 직접 반영한다.
- 단, 타겟은 장르와 목적을 대체하지 않는다.
- 예:
  - `영유아`: 문장 짧게, 개념 한 번에 하나씩, 관계 단순화, 반복 강화
  - `중장년`: 실용성과 맥락 설명 강화

### 4.4 Viewing Purpose(시청 목적)
- 본 항목은 단순 참고값이 아니라 `이 영상이 왜 소비되는가`를 뜻한다.
- 시청 목적은 전개 구조와 장면 우선순위를 실제로 바꿔야 한다.
- 예:
  - `학습`: 개념 제시, 반복, 복습, 이해 확인
  - `놀이`: 참여, 리듬, 호응, 따라 하기
  - `실용 정보`: 요점 우선, 군더더기 최소화
- 따라서 본 문서 기준에서 `시청 목적`은 더 이상 약한 니즈 항목으로만 취급하지 않는다.

### 4.5 Duration(영상 길이)
- 길이는 씬 개수만 정하는 값이 아니다.
- 길이에 따라 씬 역할, 정보량, 반복 횟수, 전개 속도가 달라져야 한다.
- 특히 15초, 30초, 45초 같은 짧은 구간은 전용 블루프린트를 우선 적용한다.

### 4.6 Tone(개요 톤)
- 톤은 이번 영상의 정서와 말투를 결정한다.
- 톤은 `분위기 라벨`이 아니라 씬 안에 드러나는 구체 행동/대사 조건으로 변환되어야 한다.
- 예:
  - `유머`: 귀여운 실수, 상황 반전, 웃음 비트 최소 1회
  - `차분`: 과도한 동작 억제, 안정적 설명
- 톤이 선택되었는데 결과물에서 그 톤의 증거를 찾을 수 없으면 실패로 본다.

### 4.7 Style(스타일)
- 스타일은 시각 룩, 질감, 조명, 색감, 공간감에 영향을 준다.
- 스타일은 내러티브 목적을 덮어쓰면 안 된다.
- 다만 visual/shot 단계에서는 선택 스타일을 실제 생성 힌트로 풀어 써야 한다.

### 4.8 Brand Rules / Manual Directives / Banned Expressions
- 브랜드 규칙, 수동 지시사항, 금지 표현은 최우선 하드 제약이다.
- 요약하거나 느슨하게 바꾸지 않는다.
- 충돌 시 개요 톤, 스타일, 일반 장르 규칙보다 우선한다.

## 5. 생성 아키텍처 규정

### 5.1 Scenario Spec 단계
- 시나리오 생성 전 반드시 `Scenario Spec`을 만든다.
- Scenario Spec은 최소 아래 항목을 포함해야 한다.
  - 핵심 주제 해석
  - 장르/세부 장르 실행 규칙
  - 타겟 난이도 규칙
  - 시청 목적 규칙
  - 톤 증거 조건
  - 스타일 잠금 조건
  - 길이별 씬 블루프린트
  - 하드 제약 / 소프트 선호

### 5.2 Scene Blueprint 단계
- 모델 호출 전에 각 씬의 역할을 먼저 정한다.
- 예: 15초 학습형 영상
  - Scene 1: 관심 끌기
  - Scene 2: 핵심 제시
  - Scene 3: 따라 하기/반복
  - Scene 4: 복습/마무리
- 씬 역할이 없는 자유 생성은 지양한다.

### 5.3 Prompt 단계
- System Prompt에는 아래가 명시되어야 한다.
  - 개요는 반드시 지켜야 하는 계약이라는 점
  - 장르/세부 장르/목적/톤별 강제 조건
  - 실패로 간주되는 출력 예시
  - 씬 수, 씬 역할, 필수 필드
- User Prompt에는 아래가 구조화되어야 한다.
  - Topic 원문
  - Topic 해석 결과
  - Scenario Spec 요약
  - 씬별 블루프린트
  - 브랜드 규칙과 수동 지시사항 원문

### 5.4 Validation 단계
- 생성 직후 아래 항목을 검사한다.
  - 주제 핵심 행위 반영 여부
  - 장르/세부 장르 적합 여부
  - 타겟 난이도 적합 여부
  - 시청 목적 적합 여부
  - 톤 증거 존재 여부
  - 길이와 씬 구조 적합 여부
- 검사를 통과하지 못하면 다음 중 하나를 수행한다.
  - 문제 씬만 국소 교정
  - 전체 재생성
  - 폴백 템플릿 적용

## 6. 장르/목적/톤 규칙 사전 구축 방침
- 옵션 목록만 저장하는 방식에서 벗어나, 각 값에 대응되는 `서술 규칙`과 `검사 기준`을 함께 관리한다.
- 최소 관리 단위는 아래 두 가지다.
  - `generationRules`: 생성 시 반드시 반영할 규칙
  - `validationRules`: 생성 후 검사할 기준
- 예시:
  - `키즈 놀이`
    - generationRules: 참여 유도 문장 포함, 동작 중심, 짧은 반복
    - validationRules: 시청자 따라 하기 요소 1회 이상
  - `유머`
    - generationRules: 귀여운 실수 또는 상황 개그 포함
    - validationRules: 웃음 포인트 또는 반전 비트 1회 이상
  - `학습`
    - generationRules: 제시, 반복, 복습 포함
    - validationRules: 개념 제시 장면과 반복 장면이 모두 존재

## 7. 길이별 블루프린트 규정
- 15초: 한 가지 목표만 다룬다. 도입, 핵심, 반복, 마무리 중심.
- 30초: 핵심 목표 1개와 짧은 응용 1개까지 허용.
- 45초 이상: 설명, 예시, 반복, 응용, 회수 구조를 확장 가능.
- 길이가 짧을수록 `정보량 추가`보다 `명확한 구조`를 우선한다.

## 8. 비주얼/카메라 규정
- 카메라 연출은 중요하지만 시나리오 본질을 압도하면 안 된다.
- 우선순위는 아래와 같다.
  1. 개요 충실도
  2. 씬 역할 충실도
  3. 타겟/목적/톤 적합도
  4. 비주얼/카메라 구체화
- 카메라 문구 자동 보강은 내용 적합도 검사 이후 단계에서 수행하는 것이 바람직하다.

## 9. 폴백 규정
- 폴백은 범용 문장으로 채우지 않는다.
- 폴백도 Scenario Spec을 기반으로 최소한 아래를 지켜야 한다.
  - 주제 핵심 행위
  - 장르/세부 장르 구조
  - 타겟 난이도
  - 목적
  - 톤
  - 길이
- 즉, 실패해도 `개요와 무관한 시나리오`가 나오면 안 된다.

## 10. 구현 우선순위

### 10.1 1차 구현
- `Scenario Spec` 생성기 추가
- 장르/세부 장르/목적/톤 규칙 사전 추가
- 15초, 30초, 45초 길이별 블루프린트 추가
- 프롬프트를 `라벨 전달형`에서 `강제 조건형`으로 개편

### 10.2 2차 구현
- 생성 후 개요 적합도 검사기 추가
- 씬 단위 교정 또는 재생성 루프 추가
- 개요 기반 폴백 시나리오로 교체

### 10.3 3차 구현
- 테스트 케이스를 `형식 검증`에서 `개요 충실도 검증`으로 확장
- 대표 입력 조합에 대한 회귀 테스트 추가
- 품질 로그에 `왜 재생성되었는지` 사유 기록

## 11. 성공 판정 기준
- 결과 시나리오를 읽었을 때 사용자는 `주제만 맞는 일반 시나리오`가 아니라 `내가 설정한 개요가 그대로 반영된 결과`라고 느껴야 한다.
- 같은 Topic에 대해 장르, 타겟, 목적, 톤 중 하나만 바꿔도 결과 구조가 분명히 달라져야 한다.
- `유머`를 선택했는데 유머가 없거나, `학습`을 선택했는데 학습 구조가 없거나, `놀이`를 선택했는데 참여 요소가 없으면 실패다.
- 품질 기준은 `JSON이 정상인가`가 아니라 `개요 충실도를 통과했는가`여야 한다.

## 12. 이번 개선 작업의 직접 목표
- 개요 입력값을 강한 시나리오 생성 계약으로 승격한다.
- 시나리오 생성 결과에 대해 개요 충실도를 자동 판정한다.
- NK_Studio가 다른 자동화 도구와 차별화되는 지점을 `개요 정렬형 생성 품질`로 만든다.
