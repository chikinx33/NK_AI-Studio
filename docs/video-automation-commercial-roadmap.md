# NK_Studio 영상 생성/편집 상용화 로드맵

본 문서는 NK_Studio를 "데모 가능한 자동화 툴"에서 "상용화 가능한 최고 수준의 영상 생성·편집 엔진 및 에이전트"로 끌어올리기 위한 기준 계획서다.

## 1. 최상위 철학

### 1.1 제품 철학 선언

NK_Studio는 다음 목표를 절대 기준으로 삼는다.

- 세상에 존재하는 어떤 자동화 영상 제작/편집 툴보다 더 강력한 성능
- 더 빠른 실행 퍼포먼스와 더 높은 결과 일관성
- 더 실용적인 사용자 제어력과 더 낮은 운영 피로도
- 데모용 기능 나열이 아니라 실제 돈을 지불하고 계속 쓰게 되는 상용 제품성
- "자동 생성"을 넘어 "자동 판단, 자동 복구, 자동 최적화, 자동 운영"까지 수행하는 에이전트화

### 1.2 철학의 해석 원칙

이 철학은 마케팅 문구가 아니라 모든 우선순위와 설계 판단의 기준이다.

- 화려하지만 재현이 어려운 기능보다, 반복 생산에서 이기는 기능을 우선한다.
- 한 번 잘 나오는 결과보다, 100번 돌려도 관리 가능한 결과를 우선한다.
- 생성 품질만 높이는 방향이 아니라, 수정 비용과 실패 복구 비용을 같이 낮춘다.
- 사람을 완전히 배제하는 환상을 추구하지 않는다. 사람 한 명이 가장 강한 감독이 되도록 돕는 방향을 택한다.
- 기능 추가보다 엔진 신뢰도, 속도, 관측 가능성, 비용 효율을 먼저 확보한다.

### 1.3 절대 금지 원칙

- UI 문구로만 존재하는 기능을 구현된 기능처럼 포장하지 않는다.
- 근거 없는 "AI가 알아서" 설계를 핵심 경로에 두지 않는다.
- 생성 품질 이슈를 프롬프트 덧칠만으로 덮지 않는다.
- 운영 로그와 실패 원인 추적이 불가능한 구조를 허용하지 않는다.
- 테스트 없이 핵심 파이프라인을 확장하지 않는다.

## 2. 현재 기준점

현재 NK_Studio는 다음 수준에 있다.

- 프리프로덕션: 구조화된 시나리오 생성, 브랜드 컨텍스트 반영, fallback 보유
- 프로덕션: 씬 단위 이미지/영상 생성, 라이브러리 저장/복구, 폴링 처리
- 포스트프로덕션: 브라우저 기반 타임라인, 자막 트랙, 렌더링, MP4 트랜스코딩
- 한계: 거대한 프런트 파일 중심 구조, 약한 테스트 체계, 실TTS/편집 규칙 엔진 부재, 상용 운영 관점의 가시성 부족

즉, "가능성을 증명한 알파"이며, 이제부터는 "상용 엔진화" 단계로 전환해야 한다.

## 3. 최종 목표 상태

NK_Studio의 목표 상태는 아래 5개 축을 모두 만족하는 것이다.

### 3.1 생성 엔진

- 주제 입력만으로도 상업 품질에 근접한 기획안, 씬 구조, 비주얼 지시, 음성 스크립트 생성
- 브랜드/IP/채널 특성에 따른 자동 스타일 고정
- 실패 시 대체 전략 자동 선택

### 3.2 편집 엔진

- 컷 구성, 길이 보정, 자막 타이밍, BGM, 장면 전환, 버전 파생을 규칙 엔진으로 자동 처리
- 결과물 목적에 맞춰 쇼츠/롱폼/광고/교육형 변형 자동 생성
- 브라우저 미리보기와 서버 렌더 결과가 최대한 일치

### 3.3 에이전트 엔진

- 사용자의 목표를 해석해 필요한 생성, 편집, 수정, 복구 단계를 스스로 오케스트레이션
- 실패 원인 분석 후 재시도 전략 자동 제안 또는 자동 실행
- "이 영상이 왜 이렇게 나왔는지"와 "다음에 무엇을 바꿀지"를 설명 가능

### 3.4 상용 운영 엔진

- 프로젝트, 자산, 버전, 비용, 속도, 실패율, 품질 로그를 모두 추적
- 사용자 계정/요금제/대기열/권한/보안/저장소 정책이 안정적으로 운영
- 장애 복구와 고객 대응이 가능한 관측 체계 보유

### 3.5 성과 엔진

- 영상 생성 성공률, 편집 성공률, 렌더 성공률, 평균 처리 시간, 재시도율, 유지율이 제품 KPI로 관리
- 단순 생성툴이 아니라 "콘텐츠 생산성 시스템"으로 자리잡음

## 4. 제품 전략 우선순위

우선순위는 아래 순서를 절대 기준으로 삼는다.

### P0. 신뢰도와 구조 정상화

목표:

- 엔진이 커져도 망가지지 않는 구조 확보
- 데이터 정합성, 실패 복구, 테스트 기반 확보

왜 먼저 해야 하는가:

- 지금 상태에서 기능만 쌓으면 속도는 빨라 보이지만 상용화 직전 전체가 흔들릴 가능성이 크다.

핵심 과제:

- `pipeline.js`, `post-production.js` 분해
- 프로젝트/자산/렌더 상태 저장소 단일화
- 핵심 파이프라인 테스트 도입
- 인코딩/문자열 신뢰성 관리
- 에러 코드와 로그 스키마 표준화

성공 기준:

- 핵심 플로우 회귀 테스트 자동화
- 프로젝트 오염, 잘못된 자산 연결, 렌더 상태 꼬임 재현율 대폭 감소

### P1. 생성 품질 엔진 고도화

목표:

- 시나리오, 이미지, 영상 결과를 "잘 되면 좋다" 수준에서 "일정 수준 이상은 항상 나온다" 수준으로 끌어올린다.

핵심 과제:

- 시나리오 품질 평가 기준 도입
- 브랜드/IP 스타일 락 강화
- 프롬프트 조립기와 결과 검증기 분리
- 이미지/영상 생성 실패 유형별 자동 대체 전략 도입
- long-form chunking 품질 개선

성공 기준:

- 장르별/길이별 생성 품질 편차 축소
- 금지 표현/브랜드 충돌/장면 일관성 이슈 감소

### P2. 진짜 편집 엔진 구축

목표:

- 현재의 타임라인 UI를 넘어, 자동 컷/자막/전환/버전 파생을 규칙 엔진으로 실체화한다.

핵심 과제:

- 편집 규칙 DSL 또는 JSON 룰 스키마 정의
- 컷 길이 자동 보정 엔진
- 자막 세그먼트 엔진
- 장면 전환 엔진
- 오디오 믹싱 정책
- 쇼츠/릴스/광고/교육형 자동 재편집 프리셋

성공 기준:

- 사용자가 "다시 적용"을 누르면 실제 편집 규칙이 재계산됨
- 수동 편집 전에 이미 쓸 만한 1차 결과가 생성됨

### P3. 음성/TTS/립싱크 축 완성

목표:

- 현재 데모성 영역을 상용 축으로 전환

핵심 과제:

- 실 TTS 공급자 연결
- 화자 라이브러리/보이스 프로필
- 발화 길이 기반 자막 타이밍 생성
- 대사/나레이션 분리 렌더
- 립싱크 또는 mouth-safe 생성 전략 분기

성공 기준:

- 무음 샘플 대체 제거
- 음성 길이와 자막, 컷 길이의 상호 정합성 확보

### P4. 에이전트 오케스트레이션

목표:

- 사용자가 개별 버튼을 누르는 툴에서, 목표를 맡기면 계획하고 실행하는 에이전트로 진화

핵심 과제:

- 작업 목표 입력 모델 정의
- 작업 계획 생성기
- 실패 재시도 정책 엔진
- 단계별 승인/자동 실행 모드
- explainability 로그

성공 기준:

- "제품 소개 쇼츠 3개 만들어줘" 같은 목표를 여러 단계로 분해해 처리 가능
- 실패 시 자동 원인 분류와 대응 제안 가능

### P5. 상용 운영/배포 체계

목표:

- 고객을 받을 수 있는 운영형 시스템으로 완성

핵심 과제:

- 작업 대기열, rate limit, 과금 단위, 크레딧 정책
- 요금제 기능 제한
- 관리자용 운영 대시보드
- SLA 기준, 장애 알림, 감사 로그
- 사용자 데이터 백업/복구 정책

성공 기준:

- 유저 증가 시에도 처리 지연과 비용 폭증을 통제 가능

## 5. 단계별 개발 로드맵

## Phase 1. 엔진 기반 정리

기간:

- 즉시 착수

목표:

- "더 만들기 전에 덜 깨지는 구조" 확보

개발 항목:

- 파이프라인 상태 모델 분리
- 포스트프로덕션 렌더 로직 분리
- 자산 레퍼런스 표준 스키마 정의
- 에러/로그 코드 체계화
- 최소 테스트 세트 구축

관리 항목:

- 회귀 버그 목록화
- 핵심 시나리오 테스트 체크리스트 고정
- 기술부채 백로그 생성

릴리즈 게이트:

- 생성/편집/렌더 핵심 경로 수동 테스트 통과
- 테스트 자동화 기본선 확보

## Phase 2. 생성 품질 안정화

목표:

- 프롬프트 중심 품질 편차를 줄이고 결과 일관성을 높인다.

개발 항목:

- 시나리오 scorer
- 장면 일관성 validator
- 스타일 lock 강제기
- 실패 시 fallback 전략 매트릭스
- 모델별 출력 특성 추상화

관리 항목:

- 품질 평가셋 구축
- 장르/길이/채널별 성공 기준 정의

릴리즈 게이트:

- 평가셋 기준 충족
- 실패 케이스 자동 분류 가능

## Phase 3. 자동 편집 엔진 구축

목표:

- 문구가 아니라 실체가 있는 자동 편집 규칙 시스템 완성

개발 항목:

- 컷 계산 엔진
- 자막 타임코드 엔진
- 전환 프리셋 엔진
- BGM ducking 정책
- 장면 리타이밍 엔진

관리 항목:

- 편집 프리셋 버전 관리
- 규칙 충돌 정책 문서화

릴리즈 게이트:

- "규칙 재적용"이 실제 결과 차이로 검증 가능
- 쇼츠/롱폼 변형 결과 재현 가능

## Phase 4. 음성 및 멀티모달 완성

목표:

- 음성을 진짜 상용 축으로 전환

개발 항목:

- TTS provider abstraction
- 화자 관리 UI/데이터 모델
- 나레이션/더빙 분리 파이프라인
- 음성 기반 자막 자동 타이밍
- 보이스 품질 평가

관리 항목:

- 언어별 보이스 품질 표준
- 음성 사용량과 비용 지표 관리

릴리즈 게이트:

- 실사용 가능한 기본 보이스셋 제공
- 음성-자막-컷 정합성 확보

## Phase 5. 에이전트화

목표:

- 사용자가 세부 기능을 조작하지 않아도 목표 달성 가능

개발 항목:

- 작업 분해 planner
- 실행 orchestrator
- 복구 전략 planner
- 사용자 승인 루프
- explainable reasoning log

관리 항목:

- 자동 실행 허용 범위 정책
- 고비용 작업 승인 정책

릴리즈 게이트:

- 복수 단계 목표 작업 성공률 관리 가능
- 사람 개입 지점이 명확히 구분됨

## Phase 6. 상용화 및 확장

목표:

- 엔진, 제품, 운영을 모두 상용화 수준으로 마감

개발 항목:

- 대시보드형 운영 콘솔
- 크레딧/요금제/대기열
- 조직/권한/감사 로그
- API/SDK/외부 연동
- 퍼블리싱/채널 운영과 성과 피드백 루프 연결

관리 항목:

- SLA
- 장애 대응 매뉴얼
- 보안 및 데이터 보존 정책

릴리즈 게이트:

- 유료 사용자 운영 가능
- 장애 대응과 비용 통제 가능

## 6. 관리 체계

### 6.1 백로그 분류 체계

- Core Engine: 생성/편집/렌더 엔진 핵심
- Reliability: 테스트, 복구, 상태 정합성, 관측성
- Quality: 결과 품질, 스타일 일관성, 브랜드 반영
- Agent: 자동 계획, 자동 재시도, 설명 가능성
- Commercial: 계정, 과금, 권한, 운영, 배포

### 6.2 우선순위 판단 규칙

동일 시점에 할 일이 많으면 아래 순서로 결정한다.

1. 사용자 데이터가 꼬이거나 잃어버릴 수 있는 문제
2. 결과물 신뢰도를 깨는 문제
3. 반복 비용을 크게 높이는 문제
4. 생성/편집 품질을 올리는 문제
5. 신기하지만 핵심 흐름을 바꾸지 않는 기능

### 6.3 운영 리듬

- 주간: 버그, 실패 로그, 속도, 성공률 리뷰
- 격주: 품질 평가셋 재측정
- 월간: 로드맵 단계 점검 및 우선순위 재조정
- 분기: 상용 KPI와 기술 부채 균형 재평가

### 6.4 문서 관리 원칙

- 기능 문서와 실제 구현 상태를 분리 기록하지 않는다.
- "계획", "구현됨", "검증됨", "상용 준비" 상태를 명시한다.
- 사용자에게 노출되는 표현은 구현 수준을 넘지 않게 유지한다.

### 7.3 상용 KPI

## 8. 기술 의사결정 기준

새 기능 제안은 아래 질문을 통과해야 한다.

- 반복 제작 시간을 실제로 줄이는가
- 실패 시 원인 파악과 복구가 가능한가
- 결과 일관성을 높이는가
- 비용 대비 효과가 높은가
- 상용 운영에서 감당 가능한가

하나라도 명확히 답하지 못하면 우선순위를 낮춘다.

## 9. 반드시 먼저 해결할 현재 핵심 과제

- `prototype/ui/pipeline.js` 분해
- `prototype/js/ui/post-production.js` 분해
- 프로젝트/자산 상태 저장소 단일화
- 실 TTS 도입

- 테스트 및 관측 체계 구축

## 10. 최종 선언

NK_Studio는 "AI가 영상을 만들어준다" 수준에서 멈추지 않는다.

우리가 만드는 것은 다음이다.

- 상용화 가능한 영상 생성 엔진
- 실전형 자동 편집 엔진
- 실패를 복구하고 결과를 최적화하는 에이전트
- 크리에이터 한 명의 생산성을 극단적으로 끌어올리는 운영 시스템

앞으로 모든 기능 추가, 리팩터링, 품질 개선, 운영 설계는 이 문서의 철학과 우선순위를 기준으로 판단한다.
