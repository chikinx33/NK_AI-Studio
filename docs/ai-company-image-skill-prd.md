# AI 회사 이미지 제작 Skill PRD

> 문서 버전: 0.1
> 기준일: 2026-07-19
> Skill ID: `image`
> 입력 스키마: `company-skill/image/v1`
> 상태: 구현 준비 완료, 아직 `coming-soon`

## 1. 목표와 범위

사용자가 채팅 또는 Skill 화면에서 새 이미지 생성과 기존 이미지 편집을 요청하면 픽셀·잉크·코어가 동일한 `SkillJob`으로 후보를 만들고 비교·검수한 뒤 대표 결과와 재편집 가능한 명세를 회사 업무 탐색기에 보존합니다.

포함 범위는 `create`, `edit`, `variation`, `background-remove`, `background-replace`, `resize-extend`입니다. 카드뉴스·포스터·배너·썸네일의 전용 구성 규칙과 외부 게시는 후속 Skill 범위입니다.

## 2. 사용자 결과

- 후보 1~4개를 한 업무 안에서 비교하고 대표안을 선택합니다.
- `PNG/JPEG/WebP`, 저용량 미리보기, 생성·편집 명세, 품질 보고서, manifest를 저장합니다.
- 원본·마스크·참조 이미지의 역할과 결과 계보를 보존합니다.
- 유료 공급자 호출 전 예상 후보 수와 비용 상한을 확인합니다.
- 실패 후보도 원인과 재생성 범위를 보고서에 남깁니다.

## 3. 입력 계약

공통 봉투는 `invocationMode`, `request`, `conversationId`, `companyId`, `references`, `idempotencyKey`, `costControl`을 사용합니다. 이미지 전용 `options`는 다음을 사용합니다.

| 필드 | 필수 | 계약 |
| --- | --- | --- |
| `mode` | 예 | 여섯 작업 방식 중 하나 |
| `purpose` | 예 | 사용 목적 |
| `aspectRatio` | 예 | `1:1`, `4:5`, `3:2`, `2:3`, `16:9`, `9:16`, `custom` |
| `candidateCount` | 예 | 1~4 |
| `style` | 예 | 시각 스타일 |
| `qualityPriority` | 예 | `speed`, `balanced`, `quality` |
| `widthPx`, `heightPx` | 조건부 | `custom`이면 둘 다 256~8192 |
| `channel`, `audience`, `brandId` | 아니요 | 사용 맥락과 브랜드 |
| `editInstruction` | 조건부 | 편집·배경·확장 모드에서 필수 |
| `referenceStrength` | 아니요 | 0~1 |
| `preserveIdentity` | 아니요 | 인물·제품 일관성 유지 |
| `preserveElements`, `forbiddenElements` | 아니요 | 유지·금지 요소, 각 최대 20개 |
| `transparentBackground` | 아니요 | 투명 배경 출력 |
| `textOverlay` | 아니요 | 정확한 문구·언어·정확성 요구 |
| `outputFormat` | 아니요 | `png`, `jpeg`, `webp` |

`references[].role`은 `source`, `style`, `identity`, `product`, `mask`, `layout`을 사용합니다. 편집 계열 모드는 `source` 참조가 필수이고 부분 편집은 `mask`를 선택적으로 받습니다. 서버 정규화는 `custom` 크기, 모드별 원본, 투명 배경과 JPEG의 충돌을 검증합니다.

## 4. 공통 3열 와이어프레임

```text
┌──────── 개요 320 ────────┬──────────── 미리보기 ────────────┬──── 업무 보고 290 ────┐
│ 작업 방식                │ [후보 1] [후보 2] [후보 3] [후보 4] │ 픽셀: 시각 방향        │
│ 업무 요청·목적·대상       │ ┌──────────────────────────────┐ │ 잉크: 이미지 문구       │
│ 비율/크기·후보 수         │ │ 선택 후보 확대 / 원본 비교     │ │ 코어: 비교·선정 근거     │
│ 스타일·브랜드·참조        │ └──────────────────────────────┘ │ 품질 게이트·경고        │
│ 유지/금지 요소·텍스트      │ [원본 비교] [실사용 크기] [이력]  │ 비용·공급자·재시도       │
│ 품질/비용 우선순위         │ [대표 선택] [부분 재생성]          │ [저장] [다운로드]        │
└───────────────────────────┴──────────────────────────────────┴──────────────────────┘
```

- `OverviewFields`: 입력과 조건부 필드
- `PreviewRenderer`: 후보 그리드, 확대, 원본/결과 비교, 실제 크기
- `PreviewToolbar`: 대표 선택, 탈락, 재생성, 버전 비교
- `ReportRenderer`: 에이전트 판단, 공급자, 비용, 품질 결과
- `CompletionActions`: 저장, 형식별 다운로드, 파생 업무 생성
- `ApprovalPanel`: 비용 상한 초과와 원본 덮어쓰기 승인

모바일은 개요→미리보기→보고 순으로 쌓고 대표 선택과 다운로드를 하단 고정 동작으로 제공합니다.

## 5. 실행 흐름과 역할

1. 코어가 요청·참조·브랜드를 구조화하고 누락 조건을 검증합니다.
2. 픽셀이 시각 방향과 공급자·결정적 로컬 도구를 선택합니다.
3. 잉크가 이미지 내 정확한 문구와 금지 표현을 검수합니다.
4. 픽셀이 후보를 생성·편집하며 후보별 프롬프트·시드·공급자 응답을 기록합니다.
5. 코어가 중복·왜곡·문자·로고·참조 일관성을 비교해 대표안을 제안합니다.
6. 사용자가 대표안을 확정하거나 부분 재생성을 요청합니다.
7. 최종 파일과 source·preview·report·manifest를 저장한 뒤 `completed`로 전환합니다.

재사용 우선순위는 `/api/imagen`, `/api/imagen-describe`, `/api/upscale`, 기존 다중 `referenceImages`, 이미지 라이브러리입니다. 배경 제거·리사이즈처럼 결정적인 작업은 생성 모델보다 전용 도구를 우선하며 전용 도구가 없으면 기능을 성공으로 가장하지 않습니다.

## 6. 산출물과 저장

| 종류 | 내용 |
| --- | --- |
| `source` | 정규화 입력, 프롬프트, 참조 역할, 공급자·모델, 편집 명세 |
| `preview` | 후보 썸네일과 비교용 저용량 이미지 |
| `final` | 대표 PNG/JPEG/WebP와 선택된 추가 후보 |
| `report` | 후보별 점수, 품질 게이트, 실패·재시도, 비용 |
| `manifest` | 버전·lineage·체크섬·전체 파일 목록 |

저장 경로는 `users/{userId}/ai-company/work-library/{YYYY-MM-DD}/{workId}/`를 사용하며 후보 ID와 버전을 metadata에 둡니다. 원본을 덮어쓰지 않고 파생 버전으로 저장합니다.

## 7. 품질 게이트

- 출력 크기·화면비·형식·알파 채널이 요청과 일치합니다.
- 파일이 디코딩되고 빈 이미지나 단색 실패 결과가 아닙니다.
- 손·얼굴·제품 형태의 명백한 왜곡, 워터마크, 잘린 핵심 피사체를 탐지합니다.
- 정확 문구 요청은 OCR 결과와 비교하며 불일치는 자동 통과시키지 않습니다.
- 로고·제품·인물 참조는 색상·실루엣·핵심 특징 일관성을 검사합니다.
- 후보 간 지각 중복을 탐지하고 사실상 같은 이미지를 후보 수로 세지 않습니다.
- 실제 사용 크기에서 대비·안전 여백·가독성을 검사합니다.

자동 검사는 `passed`, `warning`, `failed`를 사용합니다. 왜곡·문자 오류·원본 누락·파일 무결성 실패는 대표안 확정을 막습니다.

## 8. 비용·권한·오류

- 후보 수×공급자 단가로 예상 비용을 계산하고 `costControl.maxAmountUsd`를 공통 게이트로 사용합니다.
- 단가를 모르면 `unavailable`로 기록하고 승인을 받습니다.
- 외부 생성은 실행 비용 승인 대상이며, 로컬 결정적 편집은 추가 외부 비용 0으로 구분합니다.
- 공급자 오류, 안전 정책 거절, 참조 손실, OCR 실패, 저장 실패를 서로 다른 재시도 단계에 기록합니다.
- 취소 시 완료 후보는 임시 보존 정책에 따르고 최종 artifact로 등록하지 않습니다.
