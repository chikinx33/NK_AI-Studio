# 스토리보드 시트 기반 일관성 구조 설계 (v2)

작성일: 2026-09-13 · 상태: 설계 확정 전(실험 P0 후 확정) · 관련 배포: v3.1660~3.1677(현행 컷 단위 파이프라인)

## 0. 한 줄 요약

일관성의 주된 근거를 "컷마다 따로 생성 + 텍스트로 설득"에서 "한 번의 생성(시트) + 그 결과물을 참조로 재현"으로 옮긴다.
세트와 캐릭터는 바이블 시트에서 한 번만 만들고, 컷은 세트별 스토리보드 시트에 6컷씩 한 장으로 그린 뒤,
컨펌된 패널을 참조로 컷별 정식 스틸을 만든다. 참조 이미지의 앵글은 항상 목표 컷의 앵글에 맞춘다.

## 1. 원칙

1. 같은 생성 안의 일관성이 가장 강하다. 컷별 독립 생성은 마지막 단계(정식 스틸)에서만 하고, 그때도 시트 패널을 1번 참조로 둔다.
2. 세트는 한 번 만든다. 이후 그 세트가 나오는 모든 컷(1분이든 29분이든)은 같은 플레이트 이미지를 참조한다. 텍스트로 세트를 다시 그리게 두지 않는다.
3. 참조의 앵글 = 목표 앵글. 모델은 참조의 구도를 베끼려 하므로, 부감 컷에는 부감 플레이트를 준다. 텍스트로 앵글을 뒤집으려 하지 않는다.
4. 창작자의 검토 단위는 시트다. 컷 하나하나가 아니라 시퀀스를 한 장에서 보고 승인·거절한다.
5. 규칙보다 자산이 우선한다. 프롬프트 규칙(화면=t=0, 배경 미서술 등)은 유지하되, 일관성 자체는 이미지 자산(시트·플레이트·시트)이 담당한다.

## 2. 산출물 계층

| 층 | 산출물 | 단위 | 참조 입력 | 컨펌 |
|---|---|---|---|---|
| L0 | 공통 헤더(스타일·팔레트·조명) | 프로젝트 | 없음 | 기존 |
| L1 | 바이블 시트 | 캐릭터 1장 + 세트당 1장(또는 합본) | 등록 캐릭터 시트, 세트 묘사 | 패널별 승인 → 크롭 저장 |
| L2 | 스토리보드 시트 | 세트별 컷 묶음(기본 6, 최대 8) | 바이블 캐릭터 패널 + 해당 세트 플레이트(목표 앵글) + 앞 시트 겹침 패널 | 패널별 승인/거절, 시트 재생성 |
| L3 | 정식 스틸 | 컷 1장 | 승인된 패널 크롭(1번) + 캐릭터 시트 + 세트 플레이트(목표 앵글) | 컷별(현행 UI) |
| L4 | 영상 | 컷 1개 또는 씬 멀티샷 | 스틸(첫 프레임) + 캐릭터/플레이트 참조 | 현행 |

### 2.1 바이블 시트 구성

- 캐릭터 시트(1장, 3×3): 캐릭터당 정면·3/4·측면(+표정 1). 캐릭터 3명이면 9칸.
- 세트 시트(세트당 1장, 2×2 또는 3×2): 인물 없는 플레이트를 기준 앵글로 — `front`(정면 아이레벨), `back`(반대편), `high`(하이앵글/부감), `low`(로우앵글). 필요 시 `left`/`right`.
- 모든 패널은 목표 화면비(16:9 등) 셀. 셀 번호만 허용, 다른 텍스트 금지.
- 승인된 패널은 크롭해 자산으로 저장한다(3.1절). 바이블은 이후 모든 시트·스틸의 참조가 된다.

### 2.2 스토리보드 시트 구성

- 격자 3×3(9칸), 셀은 목표 화면비. 1번 칸 = 그 세트의 플레이트(시트 안에서 세트를 고정하는 닻). 2~9번 = 컷(기본 6, 최대 8).
- 한 세트의 컷이 8을 넘으면 컷 순서대로 다음 시트로 나눈다. 다음 시트의 1번 칸은 앞 시트의 마지막 컷(겹침 패널)으로 바꿔 톤·조명을 잇는다.
- 세트가 바뀌면 새 시트를 시작한다(시트는 세트를 넘지 않는다).
- 셀 해상도: 2K 정사각 출력 기준 셀 약 660×370px. 이 이상 촘촘하게 하지 않는다(참조 가치 하락). 4K 모델 사용 시 상한을 12로 올릴 수 있다.

### 2.3 정식 스틸

- 참조 1번 = 승인된 패널 크롭. 지시: "이 패널을 고해상도로 재현. 구도·인물 배치·카메라 동일. 얼굴·의상 디테일은 캐릭터 시트 기준으로 복원."
- 참조 2~ = 캐릭터 시트(화면에 있는 캐릭터만), 세트 플레이트(목표 앵글).
- 생성 모드: image-to-image(편집 모드). 기존 카메라 재구성 경로를 재사용한다.
- 계보: `lineage.imageContinuity = 'sheet-panel'`, `sheetPanelRef`.

## 3. 데이터 모델

### 3.1 세트 플레이트(기존 episodeLocations 확장)

```
episodeLocations[i] = {
  id, name, description, refObjectName,        // 기존: 마스터(front)
  variants: [
    { id: 'dir-back'|'dir-left'|'dir-right',   // 기존 방위
      refObjectName, source: 'sheet'|'generated'|'upload', sheetId, panelIndex },
    { id: 'angle-high'|'angle-low'|'angle-top', // 신규 높낮이
      refObjectName, source, sheetId, panelIndex }
  ],
  sceneIds: []
}
```

- 플레이트 선택 규칙: 컷의 `cameraDirection` + `cameraElevation` → variant id 매핑(표 5.2). 없으면 마스터 + "앵글 다름" 경고. 자동 생성은 편집 모드(5.3)로만.

### 3.2 시트(신규 payload.storyboardSheets)

```
{
  id, kind: 'bible-characters'|'bible-set'|'board',
  setId,                      // board·bible-set
  cutIds: [],                 // board: 이 시트에 담긴 컷 id 순서
  grid: { cols, rows, cellAspect },
  objectName,                 // 시트 원본
  panels: [ { index, role: 'set'|'overlap'|'cut'|'character', ref: cutId|token|variantId,
              objectName /* 크롭 */, status: 'pending'|'approved'|'rejected' } ],
  prompt, referenceMeta, createdAt
}
```

### 3.3 컷(scene) 필드 추가

- `cameraElevation`: `'eye'|'high'|'low'|'top'` (컷 분해 어휘에 추가, 기본 eye).
- `sheetPanelRef`: `{ sheetId, panelIndex }`.
- 저장 화이트리스트(save.ts/get.ts·normalizeScenes·pipeline 재조립·컷 평탄화) 4곳에 모두 추가하고 체인 테스트를 둔다(기존 규칙).

## 4. 사용자 흐름

1. 시나리오 생성 → 컷 분해(현행). 분해 결과에 `cameraElevation`이 붙는다.
2. 세트·캐릭터 확정 → 바이블 시트 생성 → 시트 검토 화면에서 패널 승인 → 크롭이 자산으로 저장된다.
3. 시트 계획: 세트별로 컷을 6개씩 묶는다(최대 8). 묶음과 겹침 패널을 화면에서 보여 주고 조정할 수 있다.
4. 스토리보드 시트 생성 → 검토(패널별 승인/거절, 시트 재생성, 패널 하나만 재생성은 L3에서 처리).
5. 정식 스틸 생성: 승인된 패널만 대상으로 컷별 생성(현행 이미지 경로 재사용). 거절 패널은 다시 시트를 만들거나 L3에서 직접 생성한다.
6. 영상 생성: 현행 컷별 i2v. 선택으로 씬 멀티샷(P4).

## 5. 프롬프트 설계

### 5.1 시트 프롬프트 골격

```
[공통 헤더: 스타일·팔레트·조명]
STORYBOARD SHEET: a 3x3 grid of 9 panels, every panel exactly 16:9, thin white gutters,
small panel number in the top-left corner of each panel, no other text or captions.
Panel 1 (SET): <세트 이름> — empty set plate, <앵글>, no characters.
Panel 2 (CUT 1.1): [<사이즈>, <방위>, <높낮이>] <화면(t=0, 배경 미서술)>
...
References: image A/B = registered characters (identity only). image C = the set plate (layout, materials, lighting).
Do not merge panels. Do not change character design between panels.
```

- 컷별 문구는 현행 컷 분해의 `composition`(120자 이내)과 카메라 힌트를 그대로 쓴다.
- 캐릭터가 화면에 없는 컷(인서트)은 캐릭터 참조를 붙이지 않는다(기존 규칙).

### 5.2 앵글 → 플레이트 매핑

| cameraDirection | cameraElevation | 플레이트 |
|---|---|---|
| front | eye | master |
| back / left / right | eye | dir-* |
| any | high / top | angle-high / angle-top (없으면 편집 모드로 생성) |
| any | low | angle-low |

### 5.3 플레이트 앵글 생성(편집 모드)

- 새 이미지를 "생성"하며 참조를 붙이지 않고, 마스터 플레이트를 "편집"한다: "Show this exact set from a high angle looking down. Same layout, props, materials, lighting. No characters."
- 극단 앵글(수직 부감)은 실패율이 높다. 실패 시 2단계(인물 없는 플레이트 확인 → 인물 얹기)로 나눈다.
- 부감 컷을 만들 때는 정면 플레이트를 참조에서 뺀다(정면 참조가 섞이면 정면으로 끌린다). 앵글 지시는 프롬프트 맨 앞에 짧게.

### 5.4 다중 시트 일관성

1. 모든 시트에 바이블 패널(관련 캐릭터·해당 세트 플레이트)을 참조로 첨부한다.
2. 같은 세트의 연속 시트는 겹침 패널로 잇는다.
3. 같은 세트의 이전 시트에서 대표 패널 1장을 추가 참조한다(조명·거리감 기준).
4. 공통 헤더·모델·출력 크기를 고정한다.
5. 남은 차이는 L3에서 캐릭터 시트 기준으로 정리한다.

## 6. 격자 크롭

- 요청 격자를 고정하고 클라이언트 캔버스로 자른다.
- 여백선 검출: 행·열 밝기 프로파일에서 흰 여백 위치를 찾아 셀 경계를 보정한다. 검출 실패 시 고정 격자로 자른다.
- 크롭 결과는 GCS 업로드(objectName)해서 참조에 쓴다. data: URL은 영속화하지 않는다(기존 규칙).

## 7. 기존 장치 정리

| 장치 | 처리 |
|---|---|
| 캐릭터 시트 참조, 장소 이름 통일, 세트 플레이트 자동 첨부 | 유지(플레이트 출처만 시트 크롭으로) |
| 화면=t=0, 배경 미서술, 길이 제한, 폴백 표시, 컷 다시 나누기 | 유지 |
| 카메라 재구성(image-to-image scene 모드) | 용도 전환: L3 재현 + 5.3 플레이트 앵글 생성 |
| 4방위 플레이트 자동 생성 | 바이블 세트 시트로 대체. 개별 생성은 5.3 편집 모드로만(선택) |
| 블로킹 앵커·같은 셋업 사이즈 이동 검증기 | 선택 기능으로 강등(기본 끔). 시트 검토가 그 역할을 대신한다 |
| 이전 컷 스틸 룩 참조(look-only) | 제거(시트 패널이 대체) |
| 컷별 세트 준비 게이트(플레이트 없으면 생성) | 유지하되 "바이블 세트 시트 미승인" 안내로 바꿈 |

## 8. 실험 계획(P0 — 코드 최소, 결과로 판단)

| 실험 | 내용 | 판정 기준 |
|---|---|---|
| E1 | 바이블 캐릭터 시트 1장(캐릭터 3 × 3앵글) | 9칸 중 8칸 이상 캐릭터 동일성 유지, 번호·격자 준수 |
| E2 | 바이블 세트 시트 1장(세트 1 × 4앵글) | 앵글 4종 구분 가능, 같은 세트로 인식 |
| E3 | 스토리보드 시트 1장(세트 1, 6컷) | 컷별 사이즈·방위 지시 준수 6칸 중 5칸 이상, 패널 병합 0 |
| E4 | 패널 → 정식 스틸 3컷 | 구도 유지, 얼굴 복원, 세트 유지 |
| E5 | 편집 모드 부감 플레이트 | 3회 중 2회 이상 성공 |

실패 시 대안: 패널 수 축소(6→4), 4K 모델(Nano Banana Pro) 전환, 2단계 분리(플레이트 → 인물).
실험은 엔케 님의 실제 시나리오(ABC 동요, 세트 3)로 한다.

## 9. 구현 순서(단계마다 배포 가능)

- P0 실험: 시트 프롬프트 빌더 + 수동 생성 + 결과 공유. (코드: 프롬프트 빌더, 크롭 유틸)
- P1 자산·데이터: `cameraElevation` 어휘와 분해 프롬프트, 플레이트 variants 확장, storyboardSheets 모델과 저장 화이트리스트·체인 테스트, 바이블 시트 생성·검토·크롭 저장 UI.
- P2 스토리보드 시트: 세트별 묶음 계획, 시트 생성·검토 UI(패널 승인/거절, 시트 재생성), 겹침 패널.
- P3 정식 스틸 전환: 승인 패널 참조 경로, 앵글별 플레이트 선택, 기존 장치 강등(7절).
- P4 멀티샷 영상: Atlas Cloud의 Kling 3.0 Director / Seedance 2.0 멀티샷 지원 확인 후 씬 단위 경로 추가.

비용 추정: 이미지 수 = 바이블 1~2장 + 시트(컷 수 ÷ 6) + 정식 스틸(컷 수). 30초 7컷이면 바이블 2 + 시트 2 + 스틸 7 = 약 11장(현행: 플레이트 최대 12 + 스틸 7 = 최대 19장).

## 10. 리스크

- 패널 지시 미준수 → 시트 재생성, 패널 수 축소, 프롬프트 형식 조정(E3에서 확정).
- 격자 어긋남 → 여백선 검출 보정, 실패 시 고정 격자.
- 세트 앵글 부재 → 편집 모드 생성, 극단 앵글은 2단계 분리.
- 셀 해상도 부족 → L3 재현 필수, 필요 시 4K 모델(비용 상승).
- 서버 30초 제한 → 시트 생성은 이미지 1장 호출이라 현행과 같다. 크롭은 클라이언트.
- 옛 프로젝트 → 바이블·시트가 없으면 현행 경로로 동작(하위 호환).
