# AI 이미지 생성 흐름

## 동작

- 단일: 현재 프롬프트와 사용자가 직접 지정한 소스 이미지만 전달합니다. 이전 생성 프롬프트·이미지는 서버와 구독 큐에서 제외합니다. GPT 구독 연결 프로그램은 매 요청마다 새 임시 Codex 대화를 시작합니다.
- 대화형: 선택한 결과까지 시간순으로 최근 3개의 프롬프트와 결과 이미지를 전달합니다. 기존 인물·스타일을 이어가되 이번 지시에 명시된 변경이 우선합니다. 첫 요청에 이전 결과가 없으면 현재 지시로 생성합니다.
- 이미지를 이미지로: 단일이어도 직접 지정한 소스 이미지는 유지합니다. 소스에 특정 얼굴·복장이 있으면 이를 참고하는 것이 정상입니다. 단일은 매번 다른 인물이나 복장을 강제하는 옵션이 아니므로 동일한 설명의 결과는 비슷할 수 있습니다.

## 확인한 문제와 수정

2026-09-17 점검에서 프론트엔드는 단일 기록을 비우고 GPT 연결도 새 대화를 시작했지만, 서버가 단일 요청에 섞인 이전 기록을 강제로 제외하지 않았습니다. 또 구독 이미지 경로의 이전 결과 이미지가 큐 전달 과정에서 빠져 대화형은 이전 텍스트만 참고했습니다.

공통 이미지 서버의 생성 스타일에 따라 이전 기록을 선택하고, 구독 큐에서도 단일 기록을 차단했습니다. 구독 대화형은 이전 이미지를 인증된 경로로 읽어 소스 이미지 뒤에 첨부합니다. 각 이미지 역할을 번호로 명시하고 마스크는 마지막에 유지합니다. 허용하지 않은 이미지 URL 또는 읽지 못한 참고 이미지는 생성 전에 오류를 반환합니다. 현재 지시와 명시된 소스만 쓰도록 단일 프롬프트에도 독립 생성 지침을 전달합니다. 모드별 설명과 한·영 툴팁을 표시합니다.

## 검증

- image-generation-flow.test.mjs: 실제 프론트엔드 기록 선택, 선택 결과의 시간 경계, 모드 전환, 서버 단일·알 수 없는 모드 차단, 최근 3개 제한, 구독 대화형 이미지 전달 순서, 마스크 위치, 명시적인 단일 소스 유지, 허용되지 않은 URL 차단, 구독 큐의 이중 차단을 함수 실행으로 검증합니다.
- codex-image-connector.test.mjs: 같은 단일 요청을 반복해도 새 대화를 두 번 시작하고 이전 프롬프트를 포함하지 않는 것을 RPC 모의 실행으로 검증합니다.
- 실제 생성 모델의 얼굴·복장 차이는 비결정적인 출력이므로 이러한 테스트로 시각적인 다양성까지 보장하지 않습니다.
