# AI 이미지 플랫폼 설계 및 구현 체크리스트

## 1. 목표

본 문서는 NK_Studio에 새로 추가할 `AI 이미지 생성 서비스 플랫폼`의 설계 기준과 1차 구현 체크항목을 정의한다.

핵심 목표는 다음과 같다.

- `ai-video`와 분리된 별도 이미지 생성 서비스 루트를 가진다.
- 기존 브랜드/프로젝트 자산 체계와 충돌하지 않는다.
- 생성 결과를 `프로젝트 저장소`, `브랜드 IP`, `콘텐츠 저장소` 흐름으로 연결할 수 있어야 한다.
- 기존 플랫폼과 동일하게 `한/영`, `다크/라이트 테마`를 공통 적용한다.

## 2. 서비스 경계

### 2.1 ai-video

- 브랜드 허브
- 브랜드 스튜디오
- 프리프로덕션 / 프로덕션 / 포스트프로덕션
- 프로젝트/브랜드 귀속 자산

### 2.2 ai-image

- 자유 텍스트 to 이미지 생성
- 자유 이미지 to 이미지 생성
- 생성 세션 단위 탐색/변형 작업
- 생성 결과를 기존 프로젝트/브랜드 체계로 등록하는 입구

핵심 원칙:

- `ai-image`는 `ai-video`의 하위 기능이 아니다.
- `ai-image`는 별도 서비스 루트를 가지되, 자산 등록은 기존 운영 체계와 연결되어야 한다.

## 3. 권장 스토리지 구조

```text
users/
  {userId}/
    ai-video/
      brands/
        {brandId}/
          ip/
          ...
      projects{projectId}/
        image/
        videos/
        reference/
        ...
    ai-image/
      sessions/
        {sessionId}/
          outputs/
          meta.json
    userdata/
      ...
```

원칙:

- `ai-video`는 브랜드/프로젝트 귀속 자산 루트다.
- `ai-image`는 자유 생성 및 탐색 세션 루트다.
- 프로젝트나 브랜드에 공식 등록하기 전까지는 `ai-image/sessions`에 머문다.

## 4. 자산 흐름 원칙

### 4.1 생성

- 텍스트 to 이미지 결과는 기본적으로 `ai-image/sessions/{sessionId}/outputs/`에 저장한다.
- 이미지 to 이미지 결과도 동일 경로에 저장한다.

### 4.2 불러오기

1차 구현:

- 현재 선택된 프로젝트의 이미지 저장소에서 소스를 불러올 수 있어야 한다.
- 업로드한 로컬 이미지를 소스로 사용할 수 있어야 한다.

확장 구현:

- 브랜드 IP 라이브러리에서 소스를 불러오기
- 콘텐츠 저장소 이미지 자산에서 소스를 불러오기
- ai-image 이전 세션 결과를 다시 불러오기

### 4.3 등록

1차 구현:

- 생성 결과를 현재 선택 프로젝트의 이미지 저장소로 등록

확장 구현:

- 브랜드 IP 라이브러리로 등록
- 콘텐츠 저장소 이미지 자산으로 등록
- 여러 프로젝트에 참조 연결

## 5. 데이터/메타데이터 원칙

생성 결과는 최소 아래 정보를 가져야 한다.

- `sessionId`
- `resultId`
- `mode`
  - `text-to-image`
  - `image-to-image`
- `prompt`
- `sourceImageRefs`
- `aspectRatio`
- `createdAt`
- `objectName`
- `signedUrl`
- `savedTargets`
  - `project:{projectId}`
  - `brand:{brandId}`

## 6. UI 원칙

레퍼런스 UI를 참고하되, 현재 플랫폼의 공통 규칙을 유지한다.

- 좌측 패널
  - 생성 모드 탭
  - 소스 이미지 영역
  - 프롬프트 입력
  - 비율 선택
  - 생성 버튼
- 우측 패널
  - 결과 히스토리
  - 큰 미리보기
  - 다운로드
  - 프로젝트 저장소 등록

공통 적용:

- 한/영 전환
- 다크/라이트 테마
- 전역 로딩 연출
- 공통 버튼/입력 스타일

## 7. 서버 설계 원칙

### 7.1 기존 `/api/imagen` 재사용

1차 구현은 이미지 생성 API를 새로 만들지 않고 기존 `/api/imagen`을 확장한다.

추가 입력:

- `storageService`
  - `ai-video`
  - `ai-image`
- `sessionId`
- `generationMode`
  - `text-to-image`
  - `image-to-image`

### 7.2 저장 경로 규칙

- `storageService=ai-video`
  - 기존 `projects{projectId}/image/`
- `storageService=ai-image`
  - `sessions/{sessionId}/outputs/`

## 10. 구현 원칙

- 근본 원인 해결을 우선한다.
- 같은 이미지를 여러 경로에 불필요하게 중복 저장하지 않는다.
- 생성 세션 자산과 브랜드 공식 자산을 같은 폴더 정책으로 섞지 않는다.
- 1차 구현은 실제로 사용할 수 있는 최소 기능부터 완성한다.
