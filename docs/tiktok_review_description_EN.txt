## 1. What NK AI Studio does

NK AI Studio (https://nkstudio.org) is a web-based content production and brand
management platform for individual creators and small brand owners.

Inside our editor a user plans a campaign, generates the script, images, video and
voice-over, and reviews the finished asset. Only after the user explicitly approves
that exact asset on screen is it published to the user's OWN connected social
accounts. After publishing, the user can see how each post performed and use that
to plan the next one. TikTok is one of the supported destinations, alongside
YouTube, Instagram, Facebook, Threads and X.

Nothing is ever posted automatically, on a schedule, or in bulk. Every single post
requires a human confirmation step in which the caption, the media, the audience
setting and the content disclosures are shown before the post is sent.

A public page describing this integration in detail, with screenshots of every step,
is available at https://nkstudio.org/tiktok

## 2. Products and scopes we are requesting

We request three scopes: user.info.basic (Login Kit), video.publish (Content Posting
API - Direct Post) and video.list (Display API). We are NOT requesting video.upload.

--- 2.1 user.info.basic (Login Kit) ---

WHERE IT IS TRIGGERED
Settings > SNS Connections > "Connect TikTok". The user is redirected to TikTok's
authorization page and, after granting consent, returns to
https://nkstudio.org/auth/tiktok/callback

WHAT WE READ
We call /v2/user/info/ exactly once, immediately after the OAuth token exchange, and
request only these fields: open_id, display_name, username.

HOW THE DATA IS USED
- display_name and username are shown on the SNS Connections screen and again in the
  publish confirmation dialog, so that before approving a post the user can visually
  confirm WHICH TikTok account the content will be sent to. Our users often manage
  more than one brand account, so this is essential to prevent posting to the wrong
  account.
- open_id is used as the internal key that binds the stored access token and the
  performance data to the correct TikTok account.

WHAT WE STORE
open_id, display_name, username, and the access/refresh tokens. Nothing else. We do
not read or store followers, following, likes, bio, avatar, or any other profile data.

NOTE
We do not use TikTok as an identity provider. Users sign in to NK AI Studio with
their own NK AI Studio account. TikTok authorization is used solely to establish the
publishing connection.

--- 2.2 video.publish (Content Posting API - Direct Post) ---

WHERE IT IS TRIGGERED
Publish > Review & Approve > "Publish to TikTok". This is the core feature of our
product and the reason we integrate with TikTok at all.

FLOW
1. When the user chooses to publish to TikTok, we first call
   /v2/post/publish/creator_info/query/ to retrieve the creator nickname, the privacy
   level options the account allows, the maximum video duration, and whether comment,
   duet and stitch are disabled for that creator.
2. We render a confirmation dialog built from that response. In this dialog the user:
   - sees the creator nickname and a preview of the media and caption;
   - selects the audience (privacy level) from the options returned by creator_info.
     No option is pre-selected, and the post button stays disabled until the user
     chooses one;
   - toggles Comment / Duet / Stitch, with any interaction the creator has disabled
     shown as unavailable;
   - declares whether the post is commercial content, choosing "Your brand" and/or
     "Branded content", which sets brand_organic_toggle and brand_content_toggle
     respectively, and sees the corresponding "Promotional content" / "Paid
     partnership" label notice plus links to TikTok's Branded Content Policy and
     Music Usage Confirmation.
3. Only when the user presses the confirm button do we call the publish endpoint,
   passing exactly the values the user selected. Before doing so our server queries
   creator_info once more and re-validates the submitted values against it, so that a
   request cannot ask for a privacy level the account does not allow, and so that any
   interaction the creator has disabled in their TikTok account settings is forced off
   regardless of what was submitted.
   - Video: /v2/post/publish/video/init/ with source FILE_UPLOAD. Our server reads the
     user's rendered file from their own private storage and uploads the bytes directly
     to the upload URL TikTok returns. The file is never made publicly accessible.
   - Photo: /v2/post/publish/content/init/ with post_mode DIRECT_POST, media_type PHOTO
     and source PULL_FROM_URL, because the photo endpoint requires a fetchable URL.
4. We then poll /v2/post/publish/status/fetch/ to display posting progress and, on
   completion, a link to the published post.

WHAT IS BEING POSTED
The media is content the user created inside NK AI Studio and that is stored in that
user's own private storage. We never post content the user has not seen and approved.

MEDIA DELIVERY
Videos are transferred with FILE_UPLOAD, so the file is sent from our server straight
to TikTok and is never exposed on a public URL. Photo posts must use PULL_FROM_URL, so
they are served through https://nkstudio.org/api/sns/tiktok-media, a proxy on our own
verified domain that streams the user's file only when accompanied by a short-lived
HMAC-SHA256 signed token generated at publish time.

UNAUDITED BEHAVIOUR
Until this app is approved, our server forces privacy_level to SELF_ONLY regardless
of what the user selects, so that no post created through our app can become publicly
visible before review is complete.

WHAT WE STORE
The returned publish_id and the resulting post id and URL, so the user can open their
own post from our interface and so that performance data can be matched to it.

--- 2.3 video.list (Display API) ---

WHERE IT IS TRIGGERED
Analytics > Performance dashboard, when the user opens it or presses Sync.

WHAT WE READ
Via /v2/video/list/ we request, for up to 20 of the user's most recent videos:
id, title, video_description, duration, cover_image_url, embed_link, create_time,
like_count, comment_count, share_count, view_count.

HOW THE DATA IS USED
- These are displayed to that same user as a performance table and charts, so they
  can compare how the content published through NK AI Studio performed against their
  other posts.
- cover_image_url renders the post thumbnail and embed_link links the user back to
  the original video on TikTok, so all traffic returns to TikTok.
- The aggregate view/like/comment/share counts feed our planning tool, which suggests
  what type of content the user should produce next based on what performed well on
  their own account.

WHAT WE STORE
The listed metrics plus the video id and embed link, in that user's private record,
refreshed on each sync. We never download or re-host TikTok video files, and one
user's TikTok data is never shown to any other user.

## 3. Data handling, common to all three scopes

- All TikTok data is scoped to the single NK AI Studio user who authorized it. It is
  never shared with other users, never sold, never used for advertising, and never
  used to train any model.
- Tokens and TikTok data are kept in a private per-user object in Google Cloud
  Storage, encrypted at rest, and access tokens are refreshed through
  /v2/oauth/token/ using the refresh token.
- The user can disconnect TikTok at any time from Settings > SNS Connections. This
  immediately deletes the stored tokens and all cached TikTok data. Deleting the
  NK AI Studio account deletes everything.
- Privacy Policy: https://nkstudio.org/privacy
  Terms of Service: https://nkstudio.org/terms
  Both are linked in the footer of every public page.

NK AI Studio (https://nkstudio.org) is a web platform where creators and small brands
generate content with AI (script, image, video, voice), review it, and then publish it
to their own social accounts after explicit human approval, and finally measure how it
performed. TikTok is one supported destination. Nothing is ever posted automatically or
without an on-screen confirmation step. A detailed public page with screenshots of the
whole flow is at https://nkstudio.org/tiktok

We request three scopes. We are NOT requesting video.upload.

1) user.info.basic (Login Kit). Triggered at Settings > SNS Connections > Connect
TikTok, returning to https://nkstudio.org/auth/tiktok/callback. We call /v2/user/info/
once and read only open_id, display_name, username. display_name and username are shown
on the connections screen and in the publish confirmation dialog so the user can verify
which TikTok account a post will go to (our users manage multiple brand accounts).
open_id binds the stored token and the performance data to the right account. We store
only those three fields plus the tokens. We never read followers, following or likes,
and we do not use TikTok as a login provider for our own product.

2) video.publish (Content Posting API - Direct Post). Triggered at Publish > Review &
Approve > Publish to TikTok. We first call /v2/post/publish/creator_info/query/ and
build a confirmation dialog from the response: creator nickname, media and caption
preview, an audience (privacy level) selector limited to the returned options with no
pre-selected value, Comment/Duet/Stitch toggles that respect the creator's disabled
settings, and a commercial content disclosure offering "Your brand"
(brand_organic_toggle) and "Branded content" (brand_content_toggle) with the matching
Promotional content / Paid partnership notice and links to TikTok's Branded Content
Policy and Music Usage Confirmation. Only after the user confirms do we publish, and our
server first re-queries creator_info and re-validates the submitted values against it,
so a request cannot use a privacy level the account disallows and any interaction the
creator has turned off is forced off. Videos go to /v2/post/publish/video/init/ with

Photos go to /v2/post/publish/content/init/ with post_mode DIRECT_POST, media_type PHOTO
and source PULL_FROM_URL, served from our own verified domain via

We then poll /v2/post/publish/status/fetch/ for progress. Until this app is approved we
force privacy_level to SELF_ONLY server-side so nothing can become public before review.

3) video.list (Display API). Triggered on the Analytics dashboard. Via /v2/video/list/
