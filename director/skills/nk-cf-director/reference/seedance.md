# Seedance 2.5 운용

Atlas Cloud `bytedance/seedance-2.5/*` 기준이다. 사양은 2026-10-13에 조회했다. 오래됐으면 공급자 문서로 다시 확인한다.

## 1. 사양 요약

| 항목 | 값 |
|---|---|
| 모델 | `bytedance/seedance-2.5/reference-to-video`(R2V, 기본). 그 밖에 `text-to-video`, `image-to-video`, `draft-complete` |
| 참조 | 이미지 최대 30장(300~6000px, 비율 0.4~2.5, <30MB). 영상 최대 10개(합계 30초 이내, 각 2~30초, 24~60fps, ≤200MB). 오디오 최대 10개(합계 30초) |
| 길이 | 4~30초. 편집 모드는 `-1`(입력 영상 길이를 따름) |
| 해상도 | 네이티브 `480p`/`720p`/`1080p`. `-sr`/`-esr`은 낮은 해상도 생성 후 업스케일하는 별도 상품이고 가격이 다르다 |
| 비율 | `16:9` 등 명시. `adaptive`는 주 참조의 비율을 따른다 |
| 출력 | `mp4`(기본) 또는 `mov`(yuv444p, 편집 반복에 유리). 1080p mov는 HEVC 4:4:4 10bit + PCM |
| 음향 | `generate_audio` 기본 켜짐. 대사·효과음이 생성된다. BGM이 섞일 수 있으니 검사가 필수다 |
| 참조 호출 | 프롬프트에서 제출 순서대로 `@Image1`, `@Video1`, `@Audio1`로 부른다 |

## 2. 실측 단가 (Atlas, 할인 적용가, 매번 갱신해서 기록)

| 날짜 | 480p(드래프트) | 1080p |
|---|---|---|
| 2026-09 | 초당 약 $0.22 | 초당 약 $0.65 |
| 2026-10-11 | 초당 약 $0.134 | 초당 약 $0.59 (draft-complete) |

- 예: 20초 = 드래프트 약 $2.7 + 완성 약 $11.9 → 합계 약 $14.5.
- 드래프트 단가가 내려도 1080p 단가는 따로 움직인다. 견적은 해상도별 실측으로 낸다.
- 참조 영상이 들어가면 그 길이도 과금 토큰에 포함된다.

## 3. 드래프트 → 완성

1. `draft: true`로 제출한다. 480p로 렌더되고 일반 480p 요금이 나간다. 응답의 예측 ID가 곧 `draft_id`다.
2. 검수와 사용자 확인을 거친다.
3. `bytedance/seedance-2.5/draft-complete`에 `{draft_id, output_format}`만 보낸다. 프롬프트·참조·길이·비율·시드·음향은 드래프트 것을 그대로 쓴다. **구도와 연기가 동일하게 1080p로 나온다.**
   - 7일 안에 몇 번이든 완성할 수 있다. 완성할 때마다 별도 과금된다.
   - 드래프트 오디오는 완성본에 그대로 이어진다. 드래프트에서 음악이 검출됐다면 완성본에도 있다. 편집에서 처리하도록 미리 알린다.
4. 드래프트가 마음에 들지 않으면 완성하지 말고 프롬프트·참조를 고쳐 **새 드래프트**를 만든다.

## 4. 부분 재생성 (문제 구간만 덧대기)

전체가 대체로 좋고 특정 구간만 틀렸을 때 쓴다.

- 범위: 문제 컷과 앞뒤 연결에 필요한 최소 구간(보통 4~8초).
- 참조: 그 구간에 필요한 인물·배경·소품·컷 스틸만 넣는다(예: 15장 → 6~7장). 디졸브가 원인이었다면 배경 참조를 하나로 통일하고 나머지 구도는 글로 지시한다.
- 프롬프트: 원래 프롬프트의 해당 구간을 가져온다. 문제를 고치는 문장은 **구체적인 물리 상태**로 쓴다(예: "the ball stops exactly against the heel of her LEFT sneaker, touching it, not beside the foot").
- 편집 연결: 부분 테이크는 원래 테이크의 같은 시간 구간을 대체한다. 시작·끝 컷의 구도가 원본과 이어지는지 확인한다.
- 실례(2026-10-12):
  - 공 굴림 4초를 참조 7장으로 다시 만들어 통과했다.
  - 엔딩 6초는 엔딩 배경·스틸을 빼고 운동장 와이드 배경 하나로 통일해 디졸브를 없앴다.

## 5. 편집 모드 (`omni_reference_task_type: edit`)

- 입력 영상 1개(4~30초), `ratio: adaptive`, `duration: -1`.
- **잘 되는 것:** 장면 전체의 배경·룩·선명도 수정(구름 제거, 건물 단순화 등). 카메라·연기가 유지된다. 시점별 수정 스틸을 참조로 주되, 한 테이크라면 스틸끼리 건물·배경이 일치해야 한다.
- **실패하는 것:** "여러 개 중 하나만 바꾸기"(차 두 대 중 한 대만 트럭으로). 편집 모드는 종류 단위로 치환해서 모든 차가 트럭이 된다.
- 개체 하나만 바꿔야 하면 → 원본 최고 화질 첫 프레임을 시작 프레임으로 고정한 I2V로 그 컷만 다시 만든다.
- 실패한 영상을 편집 모드 입력으로 쓰지 않는다(rules B1).

## 6. 시작/끝 프레임 고정은 최후 수단

- 시퀀스 결과를 본 뒤 **특정 위치·구도 문제**를 고치는 데 반드시 필요할 때만 쓴다.
- 쓰기 전에 필요성과 시작 상태(어느 프레임, 어느 해상도·세대)를 사용자에게 설명하고 구도 확인을 받는다.
- 이미지를 채택했다고 해서 그 이미지로 시작 프레임을 고정하는 데 동의한 것은 아니다. 참조로 쓰는 것과 고정하는 것은 다르다.

## 7. 실패 대응
- 공급자 콘텐츠 심사 거절: 실존 인물이나 저작권 의심 참조를 확인하고, 문제 참조를 빼거나 교체한 뒤 사용자에게 알린다.
- 비동기 실패(파라미터 충돌): `omni_reference_task_type`을 명시하면 제출 시점에 검증된다. 편집·확장 요청은 명시하는 편이 안전하다.
- 같은 실패를 같은 조건으로 반복 제출하지 않는다. 원인을 바꾸지 못하면 멈추고 보고한다.
